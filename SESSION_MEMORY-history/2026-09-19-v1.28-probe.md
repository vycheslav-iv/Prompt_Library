## 3. Проблемы, которые встречались (и как решали)

- **`python -m py_compile` на JS-файле** — моя ошибка вызова (передал оба файла
  в py_compile); лечится раздельно: `py_compile` только для `.py`,
  `node --check` для `.js`. Оба в итоге OK.
- **Нужно ли бампать `PL_JS_VERSION`?** — нет: классы-якоря не меняют поведение,
  смоук ждёт `1.28-pickup` и проходит. Маркер бампается только под видимые изменения.
- **Probe-файлы vs конвенция имён тестов (§1.1)** — `_probe_*` не входят в схему
  `_test_/_smoke_/_audit_`, но это диагностика, а не тесты: в регулярный прогон не
  входят, `sync.py` их не копирует (вся `tests/` игнорируется). Оставлено осознанно,
  зафиксировано в §34.3.

## 4. Что важно не сломать при продолжении работы

- **Подхват живёт только потому, что нода исполняется каждый прогон.** Не убирать
  `IS_CHANGED` и не «оптимизировать» его (см. память v1.28).
- **Классы-якоря `pl-root`/`pl-main`/`pl-scroll` удалять нельзя**, пока живы
  probe-инструменты (сниппет новой версии ищет `.pl-root` в первую очередь).
- **Вся работа с базой — под `_DB_LOCK`; рекурсия запрещена** (подхват только через
  `executed` + одноразовый токен, лимит 20, без таймеров).
- Порядок INPUT_TYPES `[mode, selected, save_folder, pickup]`; PNG-патч позиционный.
- Sizing: пол — только в `computeLayoutSize`; только boolean-стейт, никаких
  `setInterval`/`MutationObserver`; legacy `computeSize` не задавать.
- Тесты — только в `NodeName/tests/`; `sync.py` их не копирует.
- После каждого изменения исходника — сразу `python sync.py Prompt_Library`
  из корня бандла (без запроса), затем «перезапусти ComfyUI».
