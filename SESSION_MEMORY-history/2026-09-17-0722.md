## 3. Проблемы, которые встречались (и как решали)

- `dropAutoSockets is not a function` + `st is not defined` — потерянные блоки в
  незакоммиченной правке; восстановили (целы в `aa98777`).
- «В Vue контент не тянется за нодой» — причина: Vue-ветка `applyPaneLayout` пинила
  `main flex:none` и панели на 480px. Цепочка высоты в Vue есть (факты §22.9).
- «В Vue ноду можно сжать в ноль» — `min-height:0` у панелей убирал пол; вернули пол 480px.
- «Смена режима не применяет раскладку» — сигналом было только событие настроек,
  а его на этой сборке ноде не хватало; добавили перехват `LiteGraph.vueNodesMode`.
- Ломало канвас в прежней (откаченной) попытке: `computeLayoutSize` возвращал
  `Math.max(this.size[1], …)`, `minH()` был сведён к BASE_H. Вывод: canvas-ветку не менять.

## 4. Что важно не сломать при продолжении работы

- **Canvas-ветку `applyPaneLayout` и `computeLayoutSize`** — проверены живьём (§22.4).
- Порядок INPUT_TYPES `[mode, selected, save_folder]`; `widget.serialize = false` свойством;
  ноль `setTimeout` в restore; никаких вечных таймеров/наблюдателей (сверка режима — по событию).
- Не возвращать `autoFitHeight`/`calibrateFloor`/`_vueFloor`: self-lock на первом замере
  (в Vue `root` растянут → `offsetHeight` = высота ноды, а не контент).
- Синк: `python sync.py Prompt_Library` → `D:\ComfyUI_windows_portable\...` → **Ctrl+F5**
  (JS-правки не требуют рестарта сервера).
- Исходники фронтенда читать так: `...\comfyui_frontend_package\static\assets\settingStore-*.js.map`
  → `sourcesContent` (там оригинальный TS/Vue, а не минифицированный код).
