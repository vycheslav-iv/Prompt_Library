# Техническое задание (ТЗ) — Prompt Library для ComfyUI

**Версия:** v1.26 (2026-09-19: обложка из видеофайлов прогона — первый кадр через PyAV, видео в ручном превью и замена обложки существующей записи картинкой или видео (§31); в v1.25 подхват финального текста (§30), в v1.24 три режима и обложка из прогона без IMAGE-провода (§29) — тесты 213/213, смоук 65/65, аудит чист)
**Связь:** продолжение серии Prompt Keeper (v1.0 — «последний промпт», Library — «база промптов»)

## Модель «как в реальной библиотеке»

Запись = книга в категории. Каталожная карточка: **название** (title), **аннотация** (полный текст промпта),
**категория** (внутреннее поле folder, путь `Фото/Портреты`), **обложка** (превью), формуляр: создана / выдана (`created_at` / `last_used`),
★ «список чтения» (favorite). Поиск — по названию и тексту. Порядок категории: сначала новые / по названию А–Я /
сначала старые / недавно выданные. Вид — как в проводнике Windows: 🖼 Крупные (163px сетка, по умолчанию),
🎞 Средние (109px сетка), 📋 Список (82px строки); выбор запоминается в localStorage. Ничего не выдумываем —
типовые библиотечные практики.

# 1. Цель проекта

Разработать кастомную ноду для ComfyUI **Prompt Library** — библиотеку промптов с категориями, поиском и превью изображений, которая:

- автоматически сохраняет промпты и превью в процессе генерации (если опция включена);
- позволяет всегда вернуться к ранее созданным промптам;
- по необходимости выдаёт нужный промпт в рабочий процесс.

# 2. Зафиксированные решения (опрос 2026-09-13)

| Вопрос | Решение |
|--------|---------|
| Архитектура | **Одна универсальная нода** (и сохраняет, и выдаёт). Отдельные Saver/Browser не делаем |
| Категории | Эволюция: сначала **свободная строка + избранное**, затем (по решению пользователя) **дерево категорий**: категории/подкатегории `Фото/Портреты` с созданием/переименованием/удалением + **имена записей**. Слово «полки» из интерфейса убрано — везде «категории» |
| Превью | **Файл прогона** (v1.24): обложка берётся после Queue из событий `executed`, провод не нужен (§29). Вход `image` (`IMAGE,VIDEO`) остался опцией — для картинки НЕ из этого прогона. Прежнее решение (2026-09-13: только провод) отменено в v1.24 |
| Хранение | **Внешний JSON + папка превью**. Не внутри workflow/PNG (как Keeper), а общая база для всех воркфлоу |

# 3. Назначение и схема работы

Одна нода на всю работу: принимает текст проводом (`source`) или ручным вводом,
выдаёт текст в поток и сохраняет записи. Обложка больше НЕ требует провода —
она берётся из файлов этого же прогона после Queue (v1.24, §29).

```text
LLM / Keeper / ручной ввод ──source──▶ [Prompt Library] ──prompt_out──▶ CLIP Encode
                                            ▲
   LLM-цепочка ▶ финальный текст ▶ CLIP     └── 📎 Текст в базу: узел-источник (v1.25, §30)
   (провод назад не нужен: он замкнул бы граф в кольцо, а ComfyUI исполняет только DAG)
```

Три режима в одном проходе `execute()` (§29.3):
1. **📥 Запись** — сохраняет входящий текст; выход пуст (сквозь — только если выход уже подключён проводом: совместимость старых графов).
2. **📤 Выдача** — на выход идёт текст выбранной записи (если записи нет — входящий); в базу ничего не пишется.
3. **📤📥 Выдача + запись** — выдаёт и сохраняет за один прогон.

Опциональный вход `image` (`IMAGE,VIDEO`) — обложка для картинки НЕ из этого
прогона (с диска, из другого воркфлоу); сам прогон провода не требует (§29).

# 4. Хранение данных (внешнее)

## 4.1. Расположение

```text
ComfyUI/user/prompt_library/
├── library.json
└── previews/
    └── {id}.png (legacy: {id}.jpg без метаданных)
```

- `user/` переживает обновление ноды и ComfyUI — выбрано сознательно.
- Путь резолвится от рабочей копии ComfyUI в рантайме (через `folder_paths` / `__file__`-относительно, уточнить на реализации).
- Удаление ноды базу не трёт.

## 4.2. Схема записи

`library.json` — объект `{"entries": [...], "folders": [...]}` (legacy: голый список — мигрирует автоматически).

```json
{
  "id": "a3f9c1e2",
  "title": "Дайвер в латунном шлеме",
  "prompt": "portrait, soft light...",
  "folder": "Фото/Портреты",
  "favorite": false,
  "created_at": "2026-09-13T12:00:00",
  "last_used": "2026-09-14T09:00:00",
  "preview": "previews/a3f9c1e2.png",
  "media": "video"
}
```

- Старые записи мигрируют: `category` → `folder`, `title` = первые 60 символов текста.
- Пустые категории хранятся в `folders` (иначе их было бы не показать в дереве).
- Удаление категории не теряет книги: записи переезжают в корень. Переименование двигает подкатегории и записи (префикс).

- `id` — 10 hex от MD5(`dedup_hash + timestamp`).
- `media` — `video` / `image` / `null` (старые записи). Описывает ТЕКУЩУЮ обложку, поэтому обновляется вместе с ней: из провода (`_media_of()`, v1.17), из расширения файла прогона (`_is_video_file`, v1.26) или из подсказки браузера при ручном превью/замене (§31). В дедупликацию не входит; у записей без метки — `null` (без перезаписи файла).
- Дедупликация двухслойная: тот же текст уже есть в базе (**в любой папке**, `_find_text_match`) → не сохраняем вообще, предупреждаем где лежит (консоль + тост + `skipped_duplicate` в ui / `duplicate` в `/add`); иначе хеш MD5(`prompt + \n + folder`) уже есть → не сохраняем повторно (возвращаем существующий id).
- `title` — имя книги; авто: первая строка текста до 60 символов; правится в панели книги.
- Лимит: 500 последних записей, новые вставляются в начало.
- Превью: PNG-тамбнейл, длинная сторона 512px (с запасом под крупный показ; в карточках даунскейлит браузер), ресемплинг LANCZOS, со встроенным чанком `workflow` (PngInfo — как у SaveImage; compact-JSON). Если провода нет, обложка подтягивается из прогона (§29) — и для видео тоже: первый кадр снимает PyAV (v1.26, §31). `preview: null` остаётся только когда в прогоне не было ни картинок, ни видео (кэш, текстовый прогон, ручное добавление без файла). Старые JPG остаются как есть, при backfill'е workflow one-time апгрейдятся в PNG (§24.3).
- `category` оставлен дублем `folder` в записи — legacy-совместимость.

# 5. Входы

| Имя | Тип | Обяз. | Описание |
|-----|-----|-------|----------|
| `source` | `*` (ANY) | optional | Подписанный вход «Промт (вход)» — провод от LLM / Keeper / др. нод |
| `image` | IMAGE,VIDEO | optional | Двухцветный сокет превью (синий IMAGE-тензор или зелёный VIDEO-объект ядра `VideoInput`; мульти-тип через запятую — штатный механизм, как `FLOAT,INT`). Не создаёт виджета, только коннектор. VIDEO разворачивается в первый кадр через `_extract_frame()` (`get_components().images[0]`) |
| `save_folder` | STRING (скрытый виджет, схлопнут) | required | Выбор дерева как есть: `""` = «Всё», `__fav`/`__root` = служебные ветки, иначе путь папки (пишет JS при каждом клике; персистится через `extra_pnginfo`; `onConfigure` восстанавливает). Python режет `__*` в корень — записи в служебные имена не сохраняются (§23.4) |
| `mode` | COMBO `📥 Запись` / `📤 Выдача` / `📤📥 Выдача + запись` | required | Запись = автосохранение (выход пуст, сквозь — только если выход уже подключён проводом); Выдача = выход текстом выбранной книги; Выдача + запись = оба дела за один прогон (v1.24, §29) |
| `selected` | STRING (hidden-виджет) | hidden/display | id выбранной записи. Пишется из JS, персистится через `extra_pnginfo` |
| `pickup` | STRING (скрытый виджет) | hidden | id узла-источника для подхвата текста после прогона (`""` = как раньше, сохранять входящий; v1.25, §30). Видимый контрол — DOM-строка `📎 Текст в базу` |
| `extra_pnginfo` | EXTRA_PNGINFO | hidden | Для патча workflow (как в Keeper) |
| `unique_id` | UNIQUE_ID | hidden | Для патча workflow (как в Keeper) |

**Ввод промпта:** в виджет `prompt` удалён. Ручной ввод через DOM-кнопку `➕ Добавить промпт` → textarea + `💾 Сохранить промпт` (POST `/prompt_library/add`). Вход `source` — провод от LLM / Keeper.

Нативную кнопку не используем: связка «DOM-окно + нативная кнопка» даёт щель при ресайзе (апстрим issue #7942).

# 6. Выходы

| Имя | Тип | Описание |
|-----|-----|----------|
| `prompt_out` | STRING | Итоговый текст: входящий (сквозной) или текст выбранной записи (режимы `📤 Выдача` / `📤📥 Выдача + запись`); в режиме `📥 Запись` — пусто (сквозь только при подключённом выходе, §29) |

Изменение текста на выходе запрещено (кроме выбора источника) — прозрачная нода, как Keeper. Второй выход `count` не делаем — счётчик виден в hint (`Записей в категории: N`).

# 7. Логика `execute()` (Python, `prompt_library_node.py`)

```
1. mode → issue / both / save_on (по умолчанию «Запись»; legacy `use_selected` → «Выдача»)
   out_linked = _output_linked(extra_pnginfo, unique_id) — у выхода уже есть провод?
   incoming = str(source), если source — непустая строка (IMAGE/LATENT отбрасываются); display = incoming; dirty = False
   out_text = incoming; в режиме «Запись» без провода на выходе — "" (старый граф с проводом — сквозь, §29)
   если (issue или both) и selected-id найден:
       out_text = запись.prompt; запись.last_used = now; dirty = True
2. fld = _storage_folder(save_folder || kwargs.folder || kwargs.category) — legacy-фолбэк, `__*` → корень
   если save_on и incoming непустой и pickup НЕ выбран:
       wf = _snapshot_workflow(extra_pnginfo)  (deep-copy только в этой ветке)
       dup = _find_text_match(entries, incoming)  (глобально — любая папка)
       если dup: skipped = {folder, id}, новой записи нет
       иначе insert {id, hash, title=auto, prompt, folder=fld, workflow=wf, media, preview=thumbnail(image)}
       added → preview_target = id (обложку берёт JS из прогона, §29);
       существующая → бэкфилл пустых workflow/media/preview, preview_target если обложки нет
       entries = entries[:500]; добавить fld + родителей в folders
   если dirty: write library.json (атомарно: tmp + rename); _broadcast_refresh() — только при added
3. если pickup выбран (v1.25): входящий текст НЕ сохраняется (шаг 2 пропущен),
   pickup_token = _pickup_stash(pickup, fld, _snapshot_workflow(extra_pnginfo)) → токен в _PICKUP (лимит 20)
4. если extra_pnginfo + unique_id:
       патч workflow.nodes[id].widgets_values = [mode, selected, save_folder, pickup]
5. notice (mode_notice): «Запись» с подключённым выходом · подхват включён при непустом входящем тексте
6. return {"ui": {"entries": до 200 × (id, title, head≤120, folder, favorite, created_at, last_used,
                                  has_preview, has_workflow, media),
                  "folders": [...], "selected": sel, "text": [display], "skipped_duplicate": {},
                  "saved_id": [id] | [], "pickup": [токен] | [], "pickup_node": [id] | [],
                  "mode_notice": [notice]},
           "result": (out_text,)}
```

Роуты продолжают логику снаружи: `/attach_preview` (§29) доводит обложку прогона,
`/save_pickup` (§30) создаёт запись из подхваченного текста по одноразовому токену.

Требования:
- `OUTPUT_NODE = True` (нужно для `{"ui": ...}` → `onExecuted` и для `extra_pnginfo`-патча).
- `FUNCTION = "execute"`, `CATEGORY = "My_custom_nodes/Prompts"`.
- `RETURN_TYPES = ("STRING",)`, `RETURN_NAMES = ("prompt_out",)`.
- Перезапись JSON целиком под каждый сейв допустима (база маленькая).
- Пустой `folder` = корень (`""`), без `"Без категории"`.
- `**kwargs["category"]` — совместимость со старыми workflow (виджет раньше назывался `category`).

Endpoints (`server.PromptServer`): GET `list` (`{entries` без `workflow`, но с
`has_workflow`, `folders}`) / `entry?id` (полная запись, включая `workflow`) /
`preview?id` (файл из записи, guard `previews/` + jpg|png, legacy-фолбэк);
POST `add` (ручное сохранение с кнопки, без workflow; опционально `preview_data` — PNG/JPEG dataURL с диска → `previews/{id}.png`) / `favorite` / `update`
(title+prompt+folder, пересчёт hash) / `delete` (+ файл превью из записи) /
`folder_create` / `folder_rename` (движет префикс) / `folder_delete`
(записи переезжают в корень, не теряются);
POST `delete_many` (`{ids}` — массовое удаление записей, мусор игнорируется,
превью чистятся) / `folder_delete_many` (`{paths}` — массовое удаление категорий,
семантика как у одиночного) /
`attach_preview` (`{id}` + либо `{filename, subfolder, type}` — файл прогона, §29,
либо `{preview_data}` — PNG-dataURL кадра от браузера, v1.26 §31; `media` уточняет
метку типа, `force` разрешает замену готового превью; файл ищется в output/temp/
input с защитой от traversal, видео декодируется первым кадром) /
`save_pickup` (`{token, text}` — запись текста, подхваченного из узла-источника
ПОСЛЕ прогона, §30; токен одноразовый, выдаётся `execute()` в `ui.pickup`,
пустой текст → `skipped: "empty"`, дубль → `duplicate: true`).

# 8. JS-интерфейс (`web/js/prompt_library.js`)

Обычными виджетами не обойтись — нужен **DOM-виджет** внутри ноды (скил `comfyui-js-extension`).

## 8.1. Компоновка (сверху вниз)

Нативные виджеты ComfyUI (сверху вниз): `mode` (📥 Запись / 📤 Выдача / 📤📥 Выдача + запись),
скрытые `selected` + `save_folder` + `pickup` (v1.25, §30). Нет виджета `prompt` — ручной ввод через DOM-кнопку. Кнопка и автосейв пишут в открытую в дереве категорию (корень — если «Всё»).

DOM-библиотека (`addDOMWidget`, сериализация выключена):
- **Строка подхвата** `pickupRow` (22px, `flex-shrink:0`, первый ребёнок `root`): `📎 Текст в базу:` + `<select>` со списком узлов живого графа (STRING-выход или строковый виджет; своя нода, другие `PromptLibrary` и mute не предлагаются; «— из входа (провод) —» = как раньше) — v1.25, §30
- **Тогл ручного ввода**: `➕ Добавить промпт` → показывает/скрывает textarea (4 строки) + `📷 Прикрепить превью` (**картинка ИЛИ видео** с диска: картинка — даунскейл 512px через canvas, видео — первый кадр через `<video>`+canvas; оба → PNG dataURL; v1.26 §31) + `💾 Сохранить промпт` (POST `/prompt_library/add` с `preview_data` + `media`; нечитаемый файл — запись без превью + стойкая подсказка). При переключении вызывает `syncNodeSize()` для подстройки высоты
- тулбар: вид (🖼 Крупные / 🎞 Средние / 📋 Список) → порядок категории (новые / А–Я / старые / недавно выданные) → тип (Всё / 🖼 Фото / 🎬 Видео, запоминается в localStorage; записи без метки видны только во «Все») → поиск (название + текст, клиентский);
- ряд: слева список книг (`list`, `flex:1`) | справа дерево категорий (`treeBox`, `width:34%`):
  - `list` = flex column: `listHead`(22px, пустой спейсер) + `listContent`(скролл, карточки)
  - `treeBox` = flex column: `treeHead`(22px, "Категории" + "+ Категория") + `tree`(скролл)
  - Оба контейнера начинаются и заканчиваются на одном уровне (одинаковая структура)
  - `list` растягивается при ресайзе ноды (`flex:1`), `treeBox` — фиксированная доля (`34%`)
  - Обе панели — `flex:1 1 0` + `min-height:0`: заполняют отведённое место и СЖИМАЮТСЯ
    под него (свой скролл), переполнения наружу нет — соседи не перекрываются (§28)
  - Категории: 📚 Всё, ★ Избранное, 📥 Без категории + вложенные 📁 с отступом; ✏️ переименовать, 🗑 удалить с переездом книг в корень; `+ Категория` создаёт категорию, в текущей — подкатегорию);
- drag & drop (нативный HTML5, без библиотек): книга тащится на строку категории / на фон списка открытой категории (переезд через POST `update`); категория тащится в другую категорию или на 📚 Всё/📥 Без категории (переезд в корень через POST `folder_rename`); дроп на себя/внутрь себя и на текущее место — игнор; дроп-зона подсвечивается пунктиром;
- карточка: обложка, название жирным (с бейджем 🎬/📷 по `media`, текст-only через `plBadge()` — раскладку не трогает), начало текста (в списке), категория · даты, ★/🗑;
- мультивыделение на удаление: Ctrl+клик — поштучно, Shift+клик — диапазон (карточки — в порядке списка, папки — в порядке дерева; служебные ветки не помечаются; якорь диапазона ставит и обычный клик, как в проводнике); помеченные — левая акцент-полоса (`box-shadow: inset`, layout не трогает) + тёплая подложка + ☑; метки живут только в сессии, текущую папку и выбранную запись не меняют → цель сохранения (`save_folder`) всегда однозначна; режим эксклюзивный — разметка чужого типа с зажатыми Ctrl/Shift игнорируется, сброс чужих меток — только обычным кликом (затем обычное действие); bulk-бар в строке-подсказке («Помечено — … · 🗑 Удалить выбранное · ✖ Снять выделение»), шпаргалка по умолчанию, тултипы на строках; метки снимаются кнопкой, обычным кликом по любой карточке/папке, кликом по пустому месту списка/дерева (`ev.target === zone`) или Esc (слушатель на корне ноды); bulk-бар живёт в НИЖНЕЙ строке ноды (`hintRow`, фиксированные 22px, `flex-shrink:0`: подсказка и бар сменяют друг друга на одном месте — раскладка не двигается), счётчик `flex:1 1 auto` + `min-width:0` (многоточие), кнопки `flex-shrink:0` — из строки не выдавливаются (§28); удаление — через `confirm` + `delete_many`/`folder_delete_many` + один `reload()`;
- панель книги: название, категория, полный текст, формуляр (`№ id · создана · выдана` + `· 🎬 видео` / `· 📷 фото` по `media`, у старых записей без метки — без хвоста), 📋 Копировать (clipboard + fallback), ✏️/💾/✖ редактирование (POST `update`; ✖ Отмена возвращает значения из базы — с подтверждением, только если правки реально есть) — в режиме правки рядом с 💾 живут ✖ и 🖼/🎬, 🖼/🎬 **Заменить превью** (v1.26 §31: файл с диска — картинка или видео, у видео первый кадр; `attach_preview` с `preview_data`+`media`+`force`; подпись кнопки показывает текущий тип обложки; кнопка живёт ТОЛЬКО в режиме ✏️ Редактировать и спрашивает подтверждение — замена необратима).

## 8.2. Хуки LiteGraph

- `onNodeCreated` — DOM-виджет (с `computeSize` с фиксированными константами), схлопывание технических `selected`/`save_folder`, первичная загрузка через `reload()` (GET `list`). Регистрирует `app.api.addEventListener("prompt_library/refresh", plListener)` для автообновления (§26).
- `onExecuted(message)` — пришедшие `entries` → полный `reload()`; `mode_notice`/`skipped_duplicate` → нижняя стойкая строка (`hintSticky`, дубль — ещё и тост). **Не пишет** в виджет `prompt` (его больше нет).
- Слушатели `app.api` `executed` / `execution_success` — обложка из прогона (`saved_id` → `/attach_preview`, §29) и подхват текста (`pickup`/`pickup_node` → `/save_pickup`, §30); `pendingCover`/`pendingPickup`/`runTexts` чистятся на успехе и на `execution_error`, сами слушатели снимаются в `onRemoved`.
- `onConfigure(info)` — синхронный restore папки из данных воркфлоу
  (`info.widgets_values_named.save_folder`, фолбэк — `info.widgets_values[2]`
  по порядку INPUT_TYPES) + одноразовый reconcile после `reload()` (виджет
  побеждает, иначе sync-значение, мусор → корень). Ноль таймеров (§23).
  Список кандидатов подхвата пересобирается после загрузки (`refreshPickupOptions`, §30).
- `onConnectionsChange` — только сторож цикла.
- Поиск/фильтр/сортировка — чистый JS по `entries`.
- Клик по карточке → `selected = id` + панель книги (GET `entry` с кэшем). Режим **не** переключается автоматически.
- Защита от кольца (JS, без участия Python — цикл виден только по проводам): переход в выдающий режим («📤 Выдача» / «📤📥 Выдача + запись») при подключённом `image` показывает confirm «отключить IMAGE-провод?»; при отмене `mode` возвращается на «📥 Запись» (`ensureIssueSafe()` возвращает bool). Сторож `checkCycle` (`onConnectionsChange`/`onConfigure`/`onNodeCreated`) красит ноду в красный + toast, если `image` подключён И выход куда-то ведёт; снимается сам при исправлении. Переключение папки сбрасывает `detailId`, `selWidget.value` и скрывает detail-панель.
- Автосокеты (фронтенд 1.52 даёт сокет каждому виджету, `getWidgetConfig`, тип `*` — проверено в установленном бандле): у `selected`/`save_folder`/`pickup` автосокеты удаляются (`dropAutoSockets` через `removeInput`, только неподключённые). Остаются ровно два подписанных входа: `source`, `image`. Подключённые не трогаем.
- ★/🗑 записи и ✏️/🗑 папок — прямые POST на endpoints + `reload()`; удаления через `confirm()`.

## 8.3. Стиль

Тёмная тема под ComfyUI. Дерево и список со своим скроллом (max-height ~300–336px). Превью отдаёт endpoint `GET /prompt_library/preview?id=` напрямую файлом (без чтения базы: `png → jpg`; `Last-Modified` → дешёвые 304). В JS стабильный `t=created_at` (не `Date.now()` — иначе перезакачка всех превью при каждом рендере) + `loading="lazy"`.

# 9. Поиск, категории, порядок (правила)

- Поиск — по подстроке в названии + тексте + категории, case-insensitive, клиентский.
- Категория — путь через `/` (`Фото/Портреты`); нормализация режет пробелы и пустые сегменты; пусто = корень.
- Родительские категории дерева выводятся автоматически из путей записей.
- Избранное — boolean-флаг, ★-тоггл, фильтр `★ Избранное`.
- Порядок категории: сначала новые (default) / по названию А–Я (`localeCompare ru`) / сначала старые / недавно выданные (`last_used`).
- Переименование категории двигает префикс у подкатегорий и записей; удаление категории переносит её книги в корень.

# 10. Персистентность (наследие Keeper, скил `comfyui-png-persistence`)

Проблема Keeper сохраняется: workflow JSON захватывается до выполнения → виджеты пусты в PNG.

- Решение то же: патч `extra_pnginfo['workflow'].nodes[unique_id].widgets_values` на стороне Python.
- Персистим: `[mode, selected, save_folder, pickup]` (порядок = порядок INPUT_TYPES; старые массивы из 3 значений читаются — `pickup` = `""`).
- Сама база (`library.json`) в PNG не дублируется — только выбор и настройки.
- Билингва виджетов — через `locales/{lang}/nodeDefs.json` (скилы `comfyui-localization`, `comfyui-bilingual-node`), паттерн — из Keeper.

# 12. Ограничения (не делаем)

- Превью для записи, созданной вручную (`➕ Добавить промпт`) — только загрузкой файла с диска: обложки прогона у неё нет.
- Экспорт/импорт базы (TXT/JSON), облачная синхронизация.
- Пагинация/виртуализация больше 500 записей (только первые 200 в UI-пакет + поиск).
- Множественный выбор / пакетная выдача.
- Теги отдельно от папок (пока хватает полок + избранного).
- Endpoint-авторизация / многопользовательность — локальный ComfyUI, один пользователь.

# 13. Совместимость

# 18. Sizing DOM-виджета: анализ и решения (2026-09-15)

## 18.1. Три найденные проблемы и их корни

### Проблема 1: Бесконечное вытягивание вниз
**Симптом:** нода растёт без остановки при создании/загрузке.
**Корень:** `computeSize` использовал `root.scrollHeight` — полную высоту DOM-дерева.
У `list` и `tree` стоит `overflow:auto` (визуально 480px), но `scrollHeight`
считает **все** строки: 100 карточек × 200px = 20,000px → нода растягивается.
**Решение:** `computeSize` возвращает фиксированные константы из стейта виджета.

### Проблема 2: Нода «пляшет» при зуме
**Симптом:** при изменении масштаба канваса нода прыгает вверх-вниз.
**Корень:** `computeSize` делил высоту на `plScale()` (зум канваса). При зуме 0.5×
фронтенд получал высоту ×2 → растягивал ноду → `computeSize` вызывался снова →
обратная связь. Дополнительно: `offsetHeight` нестабилен во время layout-пересчётов.
**Решение:** убрано деление на `plScale()`, убран `offsetHeight` — фиксированные константы.

### Проблема 3: Пустое пространство снизу
**Симптом:** после удаления `computeSize` фронтенд даёт DOM-виджету дефолтную
высоту (~420px), которая не совпадает с реальным контентом.
**Корень:** фронтенд 1.52 не может точно вычислить высоту кастомного DOM без подсказки.
**Решение:** `computeSize` с фиксированными константами, вычисленными из реального контента.

## 18.2. Почему другие подходы не работали

| Подход | Почему не работает |
|--------|-------------------|
| `root.scrollHeight` | Считает скрытый контент `overflow:auto` → бесконечный рост |
| `offsetHeight` элементов | Нестабилен при layout-пересчётах (zoom, resize) → обратная связь |
| Деление на `plScale()` | При зуме фронтенд получает разную высоту → «танцы» |
| `fitNode` + `Math.max` | Нода может только расти,never сжиматься → застряет на максимуме |
| CSS-инъекции / таймеры / наблюдатели | Колхоз, ломается при обновлениях фронтенда |
| Override `this.computeSize` на ноде | Фронтенд использует для определения размера ноды → mismatch |

## 18.3. Текущее решение: фиксированные константы + detail max-height

```js
const DETAIL_H = 280; // detail-панель: title + folder + textarea(10rows) + meta + buttons
const BASE_H = 624;   // 596 (v1.24) + pickupRow(22) + gap(6) — см. §18.4
const INPUT_H = 170;  // toggle input area (textarea 4 rows + attach row + save button)

browserWidget.computeSize = (w) => {
    const showDetail = detail && detail.style.display !== "none";
    const showInput = inputVisible;
    return [w || this.size[0], BASE_H + (showDetail ? DETAIL_H : 0) + (showInput ? INPUT_H : 0)];
};
```

**Почему это работает:**
- Константы вычислены один раз из реального контента (см. раздел 18.4)
- `computeSize` детерминирован: одинаковый вход → одинаковый выход
- Нет обратной связи с DOM (ни `offsetHeight`, ни `scrollHeight`)
- Нет зависимости от зума (`plScale` удалён)
- Фронтенд доверяет результату и не пересчитывает

## 18.4. Вычисление констант

Контент `root` (flex column, gap:6px):

| Элемент | Высота | Как вычислено |
|---------|--------|---------------|
| `pickupRow` | 22px | строка подхвата (label + select), `flex-shrink:0` (§30) |
| `inputToggle` | 30px | padding:4px × 2 + font:12px + border:1px × 2 ≈ 30px |
| `toolbar` | 30px | padding:4px × 2 + font:12px + border:1px × 2 ≈ 30px |
| `main` | ≈480px | остаток высоты (flex:1); панели сжимаются (§28) |
| `detail` | 280px | title(28) + folder(28) + textarea(170) + meta(14) + buttons(28) + gaps |
| `hintRow` | 22px | фиксированная строка (подсказка или bulk-бар) |
| gaps (6 шт) | 36px | 6 × 6px = 36px |

**BASE_H** = 596 (v1.24) + 22 (ряд подхвата) + 6 (ещё один gap) = **624px** (без detail и input area)
**С detail** = 624 + 280 = **904px**
**С input area** = 624 + 170 = **794px**
**С detail + input area** = 624 + 280 + 170 = **1074px**

> Актуально на v1.22: `INPUT_H = 170` (v1.19 добавил ряд «📷 Прикрепить превью»);
> отдаются эти константы через `computeLayoutSize` (минимум, см. §22), а не `computeSize`.
>
> v1.23 (§28): это МИНИМУМ ноды, а не точная высота панелей. Панели — `flex:1 1 0`
> и берут остаток (`H − chrome`), сколько бы нода ни была: при ноде минимального
> размера остаток ≈ 480px (отсюда и старое значение пола). Раньше пол стоял и на
> панелях — если реального остатка было меньше (номинальный `DETAIL_H=280` <
> фактической высоты панели книги, другой шрифт/зум), контент вылезал за `root`
> и его перекрывал `detail` (рисуется позже). Теперь пол ОДИН — `computeLayoutSize`.

## 18.6. Паттерн для других DOM-виджетов ComfyUI

При создании DOM-виджета с `addDOMWidget`:

1. **Определи фиксированные высоты** каждого видимого элемента (padding + font + border)
2. **Запиши константы** в `computeSize` — без `offsetHeight`, `scrollHeight`, `plScale`
3. **Не используй** `fitNode`, таймеры, наблюдатели, CSS-инъекции для sizing
4. **Вызывай `setSize`** только при изменении visible состояния (показ/скрытие панелей)
5. **Не дели на `plScale()`** — canvas-трансформация применяется фронтендом к container div
6. **Не перезаписывай `this.computeSize` на ноде** — ломает border/resize (проверено)

Если контент динамический (список растёт) — используй `overflow:auto` с фиксированной
высотой на контейнере, `computeSize` считай по контейнеру, а не по содержимому.

# 19. Аудит ошибок (deep audit, 2026-09-15)

## 19.1. Python: isinstance(source, str) — защита от IMAGE-тензора

**Проблема:** `source` объявлен как `("*", {})` — ANY-тип. Если подключить IMAGE
(тензор), `str(source)` вернёт `"<torch.Tensor object at 0x...>"` → мусор в промпте.

**Решение:**
```python
if source is not None and isinstance(source, str):
    incoming = source.strip()
else:
    incoming = ""
```

## 19.2. Python: дедупликация через _add_entry вместо ручного кода

**Проблема:** `execute()` содержал копию логики `_add_entry()` (dedup + insert),
дублируя код. Пропущен параметр `title`.

**Решение:** `execute()` вызывает `_add_entry(entries, incoming, fld)` —
единая точка дедупликации и вставки.

## 19.3. Python: preview сохраняется ПОСЛЕ _add_entry

**Проблема:** `_save_thumbnail(image, entry_id)` требует `entry_id`, но `entry_id`
создаётся внутри `_add_entry()`. Нельзя вызвать `_save_thumbnail` до `_add_entry`.

**Решение:** сначала `_add_entry` возвращает `entry_id`, потом `_save_thumbnail`
сохраняет превью, потом patch обновляет поле `preview` в записи.

## 19.4. JS: sort comparator возвращает 0 при равенстве

**Проблема:** Компараторы `old`, `used`, `new` возвращали только `-1` или `1`,
никогда `0` при равных таймстемпах → недетерминированный порядок (мерцание списка).

**Решение:**
```js
ts(a.created_at) < ts(b.created_at) ? -1 : ts(a.created_at) > ts(b.created_at) ? 1 : 0
```

## 19.5. JS: console.log → console.debug

**Проблема:** Debug-лог `[PromptLibrary] build 20260915-audit` в production-коде
засорял консоль.

**Решение:** заменён на `console.debug`.

## 19.6. Оставлено без изменений (осознанно)

- **Race condition `_load_db()`** — нет file-locking, но `os.replace` атомарен.
  При параллельных HTTP-запросах возможна потеря данных. Приоритет: низкий
  (один пользователь, последовательные запросы).
- **`reload()` молча глотает ошибки** — по design: не спамить toast при старте.
- **Double render в `onConfigure`** — `reload()` + `.then()` вызывают render
  дважды, но это корректно (данные обновляются между вызовами).
- **`BASE_H=436`** — константа, пересчитывается при визуальных изменениях.
- **`_pl_list` без кэша** — полное чтение JSON при каждом запросе. Для <500
  записей приемлемо.

- **mode revert**: при отмене IMAGE-wire disconnect диалога режим возвращается на «📥 Запись»
- **save priority**: виджет `prompt` приоритетнее провода `source` (fallback только если виджет пуст)
- **mode before prompt**: `mode` перед `prompt` в `INPUT_TYPES` (виджет режима над окном промпта)
- **folder switch**: сброс `detailId`, `selWidget.value` и скрытие detail-панели при переключении папки

## 20.4. Что НЕ работает (для будущих агентов)

| Попытка | Почему не работает |
|---------|-------------------|
| `this.computeSize = ...` (override на ноде) | Фронтенд использует `node.computeSize()` для определения размера ноды → mismatch |
| `ResizeObserver` на `this.element` | Нода и виджет — разные DOM-элементы. ResizeObserver на ноде не влияет на виджет |
| `root.style.height = this.size[1] + "px"` | `this.size` = canvas units, не CSS pixels. Прямое присвоение создаёт mismatch |
| `offsetHeight` в `computeSize` | Создаёт обратную связь при zoom/resize (подробно — §18) |
| `scrollHeight` в `computeSize` | Считает скрытый overflow → бесконечный рост |
| Увеличение нативного textarea через rAF | Перекрывает нативные кнопки |

## 20.5. Паттерн для detail-панелей в DOM-виджетах

1. Detail **внутри root** (flex column), после основного контента
2. Основной контейнер = `flex:1; overflow:hidden` (растягивается при ресайзе)
3. List/tree внутри основного = `height:Npx; overflow-y:auto` (фиксированная высота)
4. Detail = `flex-shrink:0; max-height:320px; overflow-y:auto` (не сжимается, прокручивается)
5. `computeSize` = фиксированные константы (BASE_H + DETAIL_H)
6. **Никогда** не перезаписывайте `this.computeSize` на ноде — это ломает border/resize
7. **Никогда** не используй `root height:100%` — только `flex:1` на дочерних элементах

# 21. Эксперименты с flex stretch (2026-09-16) — НЕ УДАЛОСЬ

## 21.1. Цель

Сделать так, чтобы контент (list/tree) растягивался вместе с нодой при ресайзе
(как нормальное окно), а не был фиксированных 480px. Низ ноды должен
«примыкать» к контенту.

## 21.2. Попытки и результаты

| # | Попытка | Результат |
|---|---------|-----------|
| 1 | `flex:1` на list/tree вместо `height:480px` | **Feedback loop**: `computeSize` читает `scrollHeight` → DOM заполняет ноду → `scrollHeight` = высота ноды → бесконечный цикл. Нода растёт бесконечно |
| 2 | Offscreen measurement (cloneNode) | **Сломало всё**: clone с `flex:1` создавал бесконечную высоту |
| 3 | Убрал `computeSize` override | Нода失去了 фиксированный размер, content залипает |
| 4 | `resizable=true` + `onResize` clamps | Низ ноды не сжимается — `computeSize` возвращает min height, `onResize` не может уменьшить |
| 5 | Убрал `resizable=true` | `resizable=false` запрещает ресайс вообще — пользователь не может тянуть |
| 6 | Убрал `computeSize` override | Фронтенд даёт дефолтную высоту (~420px), не совпадающую с реальным контентом |

## 21.3. Корневая причина

`computeSize` — единственный способ фронтенду узнать высоту DOM-виджета.
Он читает `scrollHeight` (или должен возвращать фиксированную константу).
Если DOM заполняет ноду через `flex:1` → `scrollHeight` = высота ноды →
`computeSize` возвращает эту высоту → фронтенд устанавливает эту высоту → loop.

**Нельзя одновременно:**
- чтобы контент растягивался с нодой (flex:1)
- и чтобы `computeSize` возвращал детерминированную высоту

Это фундаментальное ограничение архитектуры DOM-виджетов ComfyUI.

## 21.4. Вывод (для будущих агентов)

**НЕ ПОВТОРЯТЬ:**
- `flex:1` на list/tree/content — создаёт feedback loop с `computeSize`
- Offscreen measurement с cloneNode — clone наследует `flex:1`, ломает всё
- Убирание `computeSize` — фронтенд даёт неправильную дефолтную высоту
- `resizable=true` + `onResize` — не может уменьшить ноду меньше `computeSize`
- Любые CSS-хаки для «прилипания» низа — всё создаёт обратную связь

**Единственное стабильное решение:** фиксированные константы в `computeSize`
(`BASE_H=596`, `DETAIL_H=280`, `INPUT_H=130`). Контент прокручивается
внутри фиксированных контейнеров. Нода не «прилипает» к контенту — это
компромисс, но стабильный.

## 21.5. Текущее состояние (архив: решено в §22)

- ~~Низ ноды не примыкает к контенту~~ — решено переходом на `computeLayoutSize`
  (§22): ограничение было у legacy `computeSize`, а не фундаментальным.
- Деталь истории неудачных попыток выше (§21.1–21.4) — не повторять подходы
  с чтением размеров DOM в sizing-методе.

# 22. Вертикальный stretch через computeLayoutSize (2026-09-17) — РЕШЕНО

## 22.1. Проблема

При растягивании ноды в сторону контент тянулся, при растягивании вниз —
нет: внутри оставалось пустое пространство, низ не примыкал к контенту.

## 22.2. Корень (найден в исходниках фронтенда, `settingStore-*.js`)

`_arrangeWidgets` имеет две ветки:

- виджет с legacy **`computeSize`** → `computedHeight = computeSize()[1] + 4`
  — **точная** высота, свободное место ноды ему не достаётся;
- виджет с **`computeLayoutSize`** → `{minHeight, maxHeight}` →
  `distributeSpace` отдаёт ему **всё свободное место** (лимит по умолчанию —
  бесконечность). Так работают штатные video/image-превью.

Наш `browserWidget` задавал legacy `computeSize` → 596/876px намертво.
Vue-обёртка `WidgetDOM` (`flex flex-col *:flex-1`) и так растягивает наш
`root` — растягивать было нечего, виджету всегда давали ровно 596.

## 22.3. Решение (не повтор §21)

- `browserWidget.computeSize` **убран**, вместо него
  `browserWidget.computeLayoutSize = () => ({minHeight, minWidth})`,
  где `minHeight = BASE_H + DETAIL_H + INPUT_H` по boolean-стейту
  (попутно починен пропуск `INPUT_H` в старом `computeSize`).
- CSS-цепочка: `root height:100%` → `main flex:1 1 0` →
  `listContent`/`tree`: `flex:1 1 0 + min-height:0` (заполняют окно и сжимаются;
  floor — только `computeLayoutSize`-минимум, см. §28 — панели обязаны
  сжиматься, иначе переполнение перекрывает соседей).
- Почему это не §21: `computeLayoutSize` читает только boolean-стейт
  (`display`-флаги), а не размеры DOM → детерминирован, feedback loop
  невозможен по построению.

## 22.4. Статус

Проверено живьём пользователем 2026-09-17: drag вниз тянет контент, пустоты
нет, зум без «плясок». Принято (canvas-режим).

## 22.6. Двухрежимный layout: Vue (Nodes 2.0) vs canvas (механика из исходников)

- Min width в Vue = `node.style.min-width` инлайн или 225 (`useNodeResize`);
  наш MIN_W через `setSize` туда не доходит → ставим напрямую на `[data-node-id]`
  (в канвасе элемента нет → no-op). Лечит вываливание контента вправо.
- Min height Vue меряет сам (`measureMinContentHeight`: обнуляет высоту, меряет
  контент) — низ примыкает руками: потянуть вниз до упора + сохранить workflow.
  Высокий размер при открытии = сохранённый (эпоха canvas-stretch), не баг.

Факт из исходников: Vue-обёртка `WidgetDOM` (`flex flex-col *:flex-1`) без
высоты — content-sized. Flex-цепочка (§22.3) там нечем ограничить: все карточки
наружу, скролла нет, нода растягивается и не сжимается.

Решение (★ упразднено 2026-09-17, см. §22.9): `st.applyPaneLayout()` по флагу
`Comfy.VueNodes.Enabled` (чтение по документированному Settings API:
`app.extensionManager.setting.get(id)`, фолбэк — `app.ui.settings.getSettingValue`):
~~Vue — фиксированные 480px у `tree`/`listContent` (скролл всегда, как v1.7)~~,
canvas — flex stretch. NB: чтение через `app.ui.settings` напрямую НЕ работает
(молча false) — только через `extensionManager.setting`.
`computeLayoutSize`-минимум общий для обоих режимов.

> Фиксированные 480px в Vue отменены: цепочка высоты в Vue существует (§22.9),
> поэтому там теперь та же flex-раскладка, что в канвасе. Ошибка была в том, что
> решение принималось до находки цепочки. Подписка на смену режима (`.change`)
> висит на `app.ui.settings`, а детект читает `extensionManager.setting` —
> §22.9 «Открытые проблемы» п.2.

## 22.7. Vue-режим: auto-fit через прокси размера (без борьбы с layout)

Исправление прошлой ошибки: `setSize` в Vue РАБОТАЕТ — `node.size` это Proxy,
запись коммитит в layout store (`resizeNode`, source=Canvas), а платформа не
перекоммичивает без изменений (`isSizeEqual`, сходимость встроена). Вывод
«setSize мёртв» был неверен: код hug ни разу не запустился (флаг `_vuePanes`
не присваивался), проверять было нечего. Дёргавшая проба (−120/+120) удалена.

Механика `st.autoFitHeight()` (только Vue; в канвасе stretch): панели
фиксированы → контент не зависит от размера → таргет стабилен. Chrome
калибруется минимумом, зум делится (`ds.scale`), пол из `st.minH()`, deadband
4px, антиспам при несдвинувшейся ноде и том же контенте. Вызывается на
дискретных сменах контента (конец `render()`, тоглы, `onResize` — в Vue он
редок, вреда нет). Таймеров, наблюдателей, скрапинга DOM нет. Смена коннектов
сбрасывает калибровку chrome.

## 22.8. Статус Vue-фита: НЕ работает живьём, изъян найден (2026-09-17)

Пользователь: после рестарта ComfyUI и замены ноды — абсолютно без изменений.
Круговое хождение признано, работа передана другой модели.

Честный разбор изъяна (мой): калибровка `chromeMin` самоблокируется на высокой
ноде. Первая же выборка: `chrome = nodeH − content` включает ВЕСЬ surplus
(нода 2000, контент 900 → chrome=1100) → `target = content + chrome = nodeH` →
deadband «сошлось» → больше никогда не двигается. Минимум, который может только
уменьшаться, никогда не уменьшится: чтобы узнать истинный chrome, нужен момент
примыкания, которого нет. Замкнутый круг.

Факты, установленные достоверно (не терять):
- `node.size` — Proxy, запись коммитит в layout store (`resizeNode`);
  `isSizeEqual` даёт сходимость; `measureMinContentHeight` меряет минимум по
  контенту; min-width = инлайн или 225 (`useNodeResize`).
- Детект Vue через `app.extensionManager.setting.get('Comfy.VueNodes.Enabled')`
  (напрямую `app.ui.settings` — молча false). Панели 480 + скролл в Vue работают.
- Правильное направление: chrome НЕ выводить из (высокая нода − контент);
  нужен независимый замер рамки (шапка ноды напрямую) или константа.
  Канвас-режим при этом не трогать (там stretch работает, проверено). Пол `_vueFloor` из замера оставлен как фолбэк
для минимумов.

Урок: телеметрию проверять на присвоение, прежде чем верить ей.

## 22.9. Vue-режим: растяжение контента — РЕШЕНО фактами из фронтенда (2026-09-17)

Симптом: в Nodes 2.0 при растягивании ноды вниз контент оставался 480px → пустота снизу.

Факты из живого фронтенда (`comfyui_frontend_package/static/assets/settingStore-*.js`
и его **source map** — читать исходники можно прямо из `.map`, `sourcesContent`):

| Что | Код | Следствие |
|-----|-----|-----------|
| `_arrangeWidgets` | `computeLayoutSize()` → `{minHeight, maxHeight}`; `minHeight→minSize`, `maxHeight→prefHeight→maxSize` (`?? Infinity`); `distributeSpace` отдаёт свободное место, пишет `widget.computedHeight` | виджет тянется, если у него есть `computeLayoutSize` |
| то же | `!vueNodesMode && l > t && this.setSize(...)` | в Vue нода НЕ авторастится под контент |
| `useGraphNodeManager.ts` | `hasLayoutSize: typeof widget.computeLayoutSize === 'function'` | наш виджет квалифицируется |
| `useProcessedWidgets.ts` | `gridTemplateRows = shouldExpand(type) \|\| hasLayoutSize ? 'auto' : 'min-content'` | наша строка = `auto` |
| `NodeWidgets.vue` | `flex: gridTemplateRows.includes('auto') ? 1 : undefined` | контейнер виджетов получает `flex:1` |
| `WidgetDOM.vue` | `<div class="flex flex-col *:flex-1">`, своей высоты нет | наш `root` получает `flex:1` → **реальная высота** |
| `NodeContent.vue` | `flex flex-auto grow flex-col` | тело ноды реальной высоты |

Вывод: цепочка высоты в Vue существует. Тянуть контент можно тем же приёмом, что
в канвасе (§22.3) — мешал только `applyPaneLayout`, который пинил `main flex:none`
и панели на 480px (§22.6).

Решение (Vue-ветка `applyPaneLayout`):
- `main`: `flex:1 1 0` + `min-height:0`; `tree`/`listContent`: `flex:1 1 0` +
  `min-height:0` + `height:""` (тянутся по высоте ноды, скролл внутри);
- `main`+`detail` переезжают в `scrollArea` (`flex:1 1 0`, `min-height:0`,
  `overflow-y:auto`), `root` — `overflow:hidden`: переполнение уходит в скролл;
- канвас-ветка: та же flex-раскладка панелей (main/detail — прямые дети root,
  `overflow` уводить некуда, поэтому панели сжимаются — v1.23, §28).

Удалено как тупиковое (не возвращать):
- `autoFitHeight` + `_chromeMin`/`_fitLast` — калибровка chrome самоблокируется (§22.8);
- `calibrateFloor` + `_vueFloor` — в Vue `root` растянут до высоты ноды, поэтому
  `offsetHeight` = текущая высота → минимальная высота запиралась на текущей
  (нода никогда не сжималась). Та же болезнь, что `chromeMin`.

Минимум высоты в обоих режимах — константы `st.minH()` (только boolean-стейт,
без замеров DOM). `maxHeight` НЕ задаём: он уходит в `prefHeight`, а `maxSize`
по умолчанию `Infinity` → `distributeSpace` отдаёт виджету всё свободное место.

Проверка без ComfyUI: смоук-тест `tests/_smoke_prompt_library.mjs` (в папке проекта, §25.1)
исполняет файл в Node с заглушками DOM/LiteGraph и прогоняет жизненный цикл в
ОБОИХ режимах, проверяя flex-цепочку. Ловит `ReferenceError`/`TypeError` в
`onNodeCreated` за секунды — именно так были найдены потерянные `const st` и
`dropAutoSockets`.

## 22.10. Vue: «сжатие в ноль» и смена режима без перезагрузки — РЕШЕНО (2026-09-17)

Оба симптома воспроизведены пользователем живьём и исправлены.

1. **Ноду можно было сжать «в ноль»** (панели исчезали, оставались только
   шапка/тулбар/подвал). Причина: панели в Vue получили `min-height:0` +
   `flex:1 1 0` — это было нужно для скролла, но одновременно убрало ПОЛ.
   Решение: раскладка панелей теперь ОДНА для обоих режимов —
   `flex:1 1 auto` + пол `min-height:480px` (как в канвасе). Пол работает дважды:
   контент тянется при росте ноды И нода не сжимается ниже контента.
   (v1.23, §28: пол `min-height:480px` снят с панелей — он же и перекрывал низ
   списка; минимум ноды остался в `computeLayoutSize`, а панели сжимаются.)
   Отличие Vue-ветки осталось ровно одно: `main`+`detail` лежат в `scrollArea`,
   а `root` их обрезает (`overflow:hidden`) → переполнение скроллится, а не
   вылезает за ноду.

3. **В Vue новая нода открывалась «сжатой»** (видны только шапка, виджеты,
   тулбар и подвал; списка и дерева нет). Механика (подтверждена исходниками):
   - в канвасе фронтенд сам увеличивает ноду под контент —
     `!Z.vueNodesMode && l > t && (this.setSize(...))` в `_arrangeWidgets`;
     в Vue этой ветки нет, поэтому высоту ноды задаёт только **минимальная
     высота контента** (`measureMinContentHeight`);
   - пол `min-height` на панелях в этот замер НЕ попадает: панели лежат внутри
     `scrollArea` с `overflow-y:auto`, а содержимое скролл-контейнера не
     расширяет родителя → минимальная высота = только фиксированные части (~330px).
   Решение: пол перенесён с панелей на сам `scrollArea`
   (`PANES_MIN_H` в `applyPaneLayout`): он попадает в замер и становится
   минимальной высотой ноды — нода открывается с видимой частью списка.
   В Vue панели при этом `flex:1 1 0` + `min-height:0` (заселяют видимое окно,
   свой скролл рассчитан на переполнение карточками). С v1.23 (§28) так же
   и в канвасе (scrollArea там не нужен — сжимающихся панелей достаточно).
   **21:15 (по замечанию живьём):** исходное значение было 280px — позволяло сжать
   ноду заметно сильнее, чем в старых нодах (видны ~1.5 карточки). Теперь пол —
   одна константа `PANES_MIN_H = 480` для ОБОИХ режимов (канвас: панели, Vue:
   scrollArea), т.е. минимальный размер ноды в 2.0 = как в канвасе.

2. **Смена режима canvas ↔ Vue без перезагрузки не применяла раскладку** —
   нода, созданная в канвасе, оставалась с canvas-раскладкой (`overflow` не
   обрезал, пол не совпадал с новой высотой виджета) → контент вылезал наружу.
   Причина: единственным сигналом было событие настроек. Решение — три
   независимых сигнала, все без таймеров и наблюдателей:
   - **основной:** перехват `window.LiteGraph.vueNodesMode` — это тот самый флаг,
     которым фронтенд включает Vue-рендер (`useVueFeatureFlags`:
     `watch(...) → LiteGraph.vueNodesMode`), а `window.LiteGraph` ставит
     `useGlobalLitegraph` (чанк GraphView). Обёртка — один раз на страницу
     (`plHookVueMode`), реестр нод `plModeWatchers`, отписка в `onRemoved`;
   - **страховка:** событие настроек `Comfy.VueNodes.Enabled.change`
     (`scripts/ui/settings.ts`: `dispatchChange` шлёт CustomEvent на
     `app.ui.settings`; новое значение берём из `detail.value` — стор
     обновляется ДО события, см. `applySettingLocally`);
   - **догоняющая сверка:** `render()` сравнивает `isVueNodes()` с `_vuePanes`
     и переприменяет раскладку при расхождении (одно чтение свойства).

Детект режима (`st.isVueNodes`): сначала `window.LiteGraph.vueNodesMode`
(авторитетный флаг), затем `app.extensionManager.setting.get(...)`, затем
`app.ui.settings.getSettingValue(...)`.

Проверено смоук-тестом без ComfyUI: оба режима + живая смена обоими сигналами
+ фолбэк без `window.LiteGraph`.

## 22.11. Vue: живое переключение давало УЗКУЮ ноду — РЕШЕНО (2026-09-17)

**Симптом (живьём, только при переключении в настройках canvas → Nodes 2.0
без перезагрузки):** нода появлялась «сжатой» — узкая рамка, из которой контент
вылезал (список/дерево обрезаны, ширина меньше нормальной). После F5 — нормально.

**Причина.** Ширина Vue-ноды задаётся в `LGraphNode.vue` как
`min-width: var(--min-node-width)` (дефолт 350px). Наши 470px (`MIN_W`) ставит
`st.applyNodeMinWidth` — инлайн-стилем на узел `[data-node-id]`, потому что
`setSize` в Vue ширину контейнера не определяет. Но Vue **монтирует ноду
асинхронно**: в момент смены флага `LiteGraph.vueNodesMode` элемента
`[data-node-id]` в DOM ещё нет → `root.closest("[data-node-id]")` возвращает
`null` → применение в пустоту, нода остаётся на 350px. В reload-пути то же
действие выполняет `requestAnimationFrame` в `onNodeCreated` — уже после
монтирования, поэтому «после F5 всё хорошо» (и это же объясняло прошлый
симптом «нода узкая только при живом переключении»).

**Решение** (только в `st.onModeChange`; без таймеров, наблюдателей и циклов):
`settle(again)` — `applyNodeMinWidth?.()` + `enforceMinWidth?.()` сейчас и
**один** повторный кадр через `requestAnimationFrame` (два кадра: первый — после
монтирования Vue, второй — страховка на случай кадра между флагом и рендером).

**Маркер сборки:** `1.14-vue-switch-width` (`PL_JS_VERSION`, печатается в
консоль при загрузке) — удобно отличать закешированный JS от нового.

Проверено смоук-тестом: после живого переключения флага `nodeEl.style.minWidth
=== "470px"` (заглушка `[data-node-id]` + `HTMLElement`).

## 22.5. Аудит 2026-09-17: баг персистентности (v1.7-регрессия)

Найдено тщательным ревью: в `execute()` остался хвост удалённого виджета —
`widgets_values = [mode, selected, save_folder, prompt]`, где `prompt`
не определён (NameError). `except Exception: pass` глушил ошибку →
`extra_pnginfo`-патч **никогда не применялся**: режим/выбор/папка не
переживали reopen workflow и не сохранялись в PNG (и `onConfigure`-restore
нечего было восстанавливать). Исправлено на `[mode, selected, save_folder]`
(порядок = INPUT_TYPES required), доказано headless-тестом
(`_library_root` → temp, два кейса: patch в write-режиме, выдача + `last_used`
в issue-режиме). Урок: голый `except: pass` вокруг патча прячет регрессии —
при удалении виджетов grep'ать все упоминания имени.

# 23. Восстановление папки при открытии: гонка со store hydration (2026-09-17)

## 23.1. Факты (проверены, не гипотезы)

- **Save-сторона в порядке**: в workflow-файле `widgets_values_named.save_folder`
  корректен (проверено в `Krea2_MY2.json`: `"save_folder": "Fs/FAS"`), папка
  есть в `library.json`. Потеря на вкладках без рестарта — тот же load-путь.
- **Load-сторона**: одноразовый restore в `onConfigure` (даже через `rAF` + `fetch`)
  не срабатывал — в момент проверки `save_folder`-виджет ещё пуст.
- **Вывод**: новый фронтенд применяет `widgets_values` к виджетам **асинхронно**
  (widget store hydration) после создания ноды; синхронного уведомления об
  окончании на момент исследования не найдено.
- Режим при этом восстанавливался сам (фронтенд доприменяет позже), а кастомный
  JS-стейт (`selFolder`) — нет: наш restore уже отработал и пропустил.

## 23.2. Решение (без polling): sync-из-info + одноразовый reconcile

Исследование ядра (`LGraphNode.configure`): значения виджетов применяются
синхронно, затем вызывается `onConfigure(info)` — а `info` это сами данные
воркфлоу (`widgets_values` + `widgets_values_named`). Вывод: ждать hydration
виджетов не нужно вообще.

- **Sync-fase** в `onConfigure(info)`: `save_folder` из
  `info.widgets_values_named.save_folder`, фолбэк — `info.widgets_values[2]`
  (порядок INPUT_TYPES required `[mode, selected, save_folder]`, SPEC §10;
  совпадает и со старыми 4-элементными массивами). Сразу `st.selFolder = v` —
  первый рендер после fetch уже правильная папка, кадра «Всё» нет.
- **Reconcile-fase** (один `.then` после `reload()`, без таймеров): виджет
  (если гидрация донесла) побеждает, иначе держим sync-значение, мусор
  (папка удалена из базы) → `"__all"`. Клики всегда синхронизируют виджет
  и `selFolder`, поэтому сверка никогда не спорит с пользователем.
- Попутно: `syncSaveFolder` ищет виджет заново при каждом вызове
  (не кэширует ссылку); `browserWidget.serialize = false` выставлен
  **свойством** (`options.serialize` не пробрасывается — в файле был лишний
  4-й value `pl_browser:""`).
- Промежуточный retry (`st.restoreFolder`, 5×400мс) **удалён полностью**:
  в пути restore ноль `setTimeout`. Оставшиеся в файле `setTimeout` — только
  сбросы подписей кнопок (UX-фидбэк, к restore не относятся).

## 23.3. Критерий профессионального решения (выполнен)

Ни одного `setTimeout`-retry в пути restore; restore не зависит от таймингов
фронтенда (sync из данных воркфлоу); мигание сведено к задержке fetch записей
(неустранимый минимум — список нечем рисовать, пока нет данных).

## 23.4. Служебные ветки тоже персистятся (v1.9.1)

Баг: на «Избранном» (`__fav`) / «Без категории» (`__root`) выбор сбрасывался
на «Всё» — `syncSaveFolder` маппил любой `__*` в `""`, и восстановить было
не из чего (пробел с самого начала, не регрессия).

Решение: виджет несёт выбор как есть (`""` только для `__all`), reconcile
считает валидными `__all`/`__fav`/`__root` + папки из базы. `execute()` на
входе режет `str(folder).startswith("__")` в `""` — новые записи из этих
режимов сохраняются в корень, папка `__fav` в базе невозможна. Старые файлы
(там `""`) открываются как «Всё» — что не было сохранено, не восстановить.

Проверено живьём пользователем 2026-09-17: Избранное и Без категории держатся
при переключении вкладок; Queue из этих режимов пишет в корень. Принято.

# 24. Воркфлоу в карточке: drag на канвас открывает граф (v1.10, проверено живьём)

## 24.1. Замысел

ComfyUI сохраняет изображение вместе с воркфлоу и настройками — превью в Library
несёт то же самое: карточка = промпт + превью + воркфлоу, который её создал.
Потянул карточку на канвас (или «📥 Воркфлоу» в панели книги) — открылся граф,
как при дропе PNG с workflow. Искать файлы не нужно: тут и база промптов, и воркфлоу.

## 24.2. Два слоя (оба)

1. **Превью-файл самодостаточен**: PNG 512px с чанком `workflow` (PngInfo) —
   как у SaveImage. Drag из проводника открывает воркфлоу нативно, без нашего кода.
2. **Воркфлоу в записи** (`library.json`): для drag'а с карточки и кнопки —
   без файлового round-trip. В `/list` и UI-пакете вырезан (тяжёлый), отдаётся
   флаг `has_workflow`; полный — только в `/entry` по клику.

## 24.3. Захват (Python, `prompt_library_node.py`)

- `execute()`: `_snapshot_workflow(extra_pnginfo)` — deep-copy (json round-trip)
  + кап 2МБ от патологических графов. Снапшот — pre-patch (как было на Queue).
- Минификация (вариант 1+3): `separators=(",", ":")` в снапшоте и чанке —
  данные идентичны (round-trip проверен), экономия ~4% на большом реальном
  графе (352→339 КБ), на pretty-JSON до ~20%. Старые записи — как есть.
- Новая запись: workflow в запись + `_save_thumbnail(..., workflow)` →
  `previews/{id}.png` с чанком.
- Дедуп-хит без workflow: backfill + one-time апгрейд JPG→PNG с метаданными
  (`_upgrade_preview_to_png`; старые JPG без workflow остаются как есть —
  не из чего восстановить).
- Ручное сохранение (`/add`) — без workflow (`has_workflow=false`).

## 24.4. Открытие (JS, `prompt_library.js`)

- `app.loadGraphData(workflow)` — штатный API замены графа (проверен в
  `settingStore-*.js`), всегда через confirm (деструктивно).
- Drag: `dragstart` ставит `application/x-pl-entry` (+ `text/plain` для папок);
  capture-хуки `dragover`/`drop` на `app.canvas.canvas`, один раз
  (`window.__plCanvasDropHooked`); чужое не трогаем (проверка типа, иначе return;
  свой — `stopImmediatePropagation`, чтобы файловый хендлер не сработал).
- Кнопка «📥 Воркфлоу» в панели книги (видна при `full.workflow`);
  title-подсказки на карточках; без workflow — warn-toast с объяснением.

# 26. Автообновление Library-нод (v1.21)

## 26.1. Проблема

При двух нодах (Saver — запись, Library — выдача) в одном workflow,
создание записи через Saver-нод не обновляло Library-нод автоматически.
Library-нод перечитывал `library.json` только при собственном `execute()`
(который вызывается при входящем сигнале графа). Без связи «Saver → Library»
через граф, Library молчал до нажатия «новая генерация».

## 26.2. Решение: broadcast через WebSocket

```text
Saver execute() → _save_db() → _broadcast_refresh()
  → PromptServer.instance.send_sync("prompt_library/refresh", {})
    → WebSocket → все подключённые клиенты
      → ComfyApi (EventTarget) рассылает CustomEvent(type, {detail})
        → JS: app.api.addEventListener("prompt_library/refresh", ...)
          → this._pl.reload() → GET /prompt_library/list → обновлённый UI
```

## 26.3. Python: `_broadcast_refresh()`

```python
def _broadcast_refresh():
    try:
        from server import PromptServer
        PromptServer.instance.send_sync("prompt_library/refresh", {})
    except Exception:
        pass  # ComfyUI не запущен / тесты — молча игнорируем
```

Вызывается ТОЛЬКО при `need_broadcast=True` (новая запись создана).
Не вызывается при backfill workflow/media или смене папки —
эти изменения не требуют пересоздания записей в Library-нодах.

## 26.4. JS: слушатель в `onNodeCreated`

```js
const plListener = (ev) => {
    try { if (this._pl) this._pl.reload(); } catch (e) { /* silent */ }
};
app.api.addEventListener("prompt_library/refresh", plListener);
```

`app.api` — экземпляр `ComfyApi extends EventTarget`. При получении
WebSocket-сообщения с `type="prompt_library/refresh"`:
- `this._registered.has("prompt_library/refresh")` → `true` (потому что
  `addEventListener` добавляет в `_registered`)
- `super.dispatchEvent(new CustomEvent("prompt_library/refresh", {detail}))`
- JS-слушатель получает `ev` (CustomEvent), вызывает `reload()`

**Почему не `window.addEventListener`:** ComfyUI WebSocket-сообщения
рассылаются через `ComfyApi` (EventTarget), а не через `window.dispatchEvent`.
`window.addEventListener` ловит только DOM-события и никогда не получит
WebSocket-сообщение от ComfyUI. Мёртвый код — убран.

## 26.5. Флаг `need_broadcast`

```python
need_broadcast = False
if not issue and incoming:
    dup = _find_text_match(entries, incoming)
    if dup is not None:
        entry_id, added = dup.get("id"), False
    else:
        entry_id, added = _add_entry(...)
    if added:
        need_broadcast = True   # ← новая запись!
        ...
    elif wf_copy:
        dirty = True   # backfill — broadcast НЕ нужен
```

Гарантирует, что broadcast идёт только при реальном добавлении записи.

## 26.6. Потокобезопасность

`send_sync()` вызывает `self.loop.call_soon_threadsafe(messages.put_nowait, ...)`.
`execute()` работает в worker thread ComfyUI — `call_soon_threadsafe`
потокобезопасен. Если `PromptServer.instance` недоступен (тесты, ранняя
загрузка) — `except Exception: pass` молча проглатывает.

## 26.7. Роуты тоже рассылают (v1.22)

До v1.22 broadcast шёл только из `execute()` — ручные действия (`/add` кнопкой,
`/favorite`, `/update`, `/delete*`, `/folder_*`) обновляли лишь ту ноду, что
инициировала запрос (`await reload()` у вызывающего), а соседние Library-ноды и
вторые вкладки оставались со старым списком. Теперь `_broadcast_refresh()`
вызывается после каждого изменяющего сохранения:

| Роут | Условие рассылки |
|---|---|
| `/add` | только при создании записи (дубль ничего не меняет) |
| `/favorite`, `/update` | запись найдена |
| `/delete`, `/delete_many` | реально что-то удалено |
| `/folder_create`, `/folder_rename`, `/folder_delete`, `/folder_delete_many` | всегда (дерево изменилось) |

`execute()` по-прежнему рассылает ТОЛЬКО при `added=True` (не при backfill и не
при смене папки) — флаг `need_broadcast`.

## 26.8. Снятие слушателя (v1.22)

`app.api.addEventListener("prompt_library/refresh", plListener)` вешается на
глобальный объект (`ComfyApi` живёт всю сессию), поэтому в `onRemoved` слушатель
снимается (`app.api.removeEventListener(..., st.apiListener)`) вместе со
слушателем `Comfy.VueNodes.Enabled.change`. Без снятия удалённая нода не
собиралась GC и продолжала тянуть `/prompt_library/list` на каждый broadcast —
по запросу на каждую выгрузку воркфлоу за сессию.
`ComfyApi.removeEventListener` разворачивает обёртку через `WeakMap`
(`getWrappedListener`), поэтому достаточно передать исходную функцию.

## 26.9. Синхронизация нод ОДНОЙ страницы (v1.22)

WS-сигнал (§26.2) ходит кругом через сервер: между нажатием «🗑» и обновлением
второго экземпляра ноды проходит round-trip, а если сигнал потеряется (старый кэш
JS, переподключение сокета), соседняя нода продолжает показывать удалённые
карточки и папки. Поэтому в JS есть реестр живых нод страницы:

```js
const plLiveStates = new Set();    // каждая нода добавляет сюда свой st
function plRefreshLocal(except) {  // перечитать базу у всех, КРОМЕ инициатора
    for (const s of [...plLiveStates]) if (s !== except) s.reload?.();
}
```

Все изменяющие POST идут через один помощник — забыть уведомление невозможно:

```js
st.apiPost = async (path, payload) => {
    const r = await fetch(path, { method: "POST", ... });
    if (r.ok) plRefreshLocal(st);   // соседи обновляются сразу, не ждут WS
    return r;
};
```

`onRemoved` убирает ноду из реестра (`plLiveStates.delete(st)`) вместе со снятием
слушателей (§26.8). Итог: две ноды в одном графе синхронны мгновенно (удаление
карточек и папок, ★, переименование, DnD, ручное сохранение), а вкладки — через WS.
Проверка: смоук-фазы «удаление карточки обновляет соседнюю ноду» и
«onRemoved убирает ноду из реестра» (реальная кнопка 🗑 карточки + бэкенд-стаб).

# 28. Ловушка: пол на панелях перекрывал низ списка (v1.23, 2026-09-18)

## 28.1. Симптом (живьём)

«При каких-то обстоятельствах удалил часть — и область с кнопками стала
перекрыта»: нижние карточки списка оказывались под панелью книги (detail),
т.е. у них не было видно ни текста/даты, ни ряда кнопок ★/✏️/🗑.
Воспроизводимость «по обстоятельствам» — потому что перекрытие было маргинальным:
на пару десятков пикселей.

## 28.2. Причина (механика из исходников фронтенда)

- Высота DOM-виджета = `computedHeight` (`_arrangeWidgets`): `max(minHeight,
  allocation)`, где `minHeight` — наш `computeLayoutSize()`. Свободное место
  `distributeSpace` отдаёт единственному растягиваемому виджету → `root`
  ВСЕГДА точно равен высоте виджета (`root height:100%`).
- `root` — flex column с `overflow:hidden`; дети: `inputToggle`, `inputArea`,
  `toolbar`, `main`, `detail` (рисуется ПОСЛЕ main), `hintRow`.
- Канвас-ветка `applyPaneLayout` ставила на `tree`/`listContent` пол
  `min-height:480px` (+ `flex-shrink:0` у `list`). Итого минимальная высота
  панелей ≈ 506px, а места при открытой панели книги:
  `minH(876) − chrome(≈87) − detail(реально до 320px)` ≈ 470–490px.
- Дефицит ~20–40px никуда не уходил: серые панели НЕ сжимались, `root` обрезал
  по границе (`overflow:hidden`), но внутри `main` контент выходил за его бокс
  и его перекрывал `detail` — следующий сиблинг, рисуемый поверх.
- Почему `DETAIL_H=280` не спасал: это оценка, а реальная панель книги — до
  `max-height:320px`; плюс высота chrome зависит от шрифта/зума/масштаба
  интерфейса. Ошибка в любую сторону = снова перекрытие (вот откуда
  «при каких-то обстоятельствах»).

## 28.3. Решение

1. **Пол ОДИН — `computeLayoutSize().minHeight`.** С CSS-панелей пол снят:
   `tree`/`listContent` → `flex:1 1 0` + `min-height:0` (как в Vue-ветке),
   `main` → `flex:1 1 0` + `min-height:0` + `overflow:hidden` (страховка на
   случай будущих правок). Нода не может быть меньше `BASE_H` — это гарантирует
   фронтенд (минимум из `computeLayoutSize`), а панели занимают остаток
   (при ноде минимального размера — те же ≈480px, что и раньше).
2. **Обе ветки режима теперь отличает ровно одно:** в Vue `main`+`detail` живут
   в `scrollArea` (переполнение уходит в его скролл), в канвасе — прямые дети
   `root`. Раскладка панелей одинаковая — меньше шансов на расхождение.
3. **Кнопки массового удаления — внизу (как было до v1.20).** Из `listHead`
   переехали в нижнюю строку `hintRow`: подсказка и bulk-бар сменяют друг друга
   на ОДНОМ месте (строка фиксированной высоты 22px, `flex-shrink:0`), поэтому
   появление кнопок не отжимает место у списка (ради этого их и уносили наверх
   в v1.20) и они видны там, где их ждёт пользователь.
4. **Кнопки больше не режутся.** Счётчик — `flex:1 1 auto` + `min-width:0`
   (многоточие), кнопки — `flex-shrink:0`. Раньше счётчик в `listHead`
   (`white-space:nowrap` без `flex`/`min-width`) имел `min-width:auto` = ширину
   текста, поэтому при метке многих записей выдавливал `🗑 Удалить`/`✖` за правый
   край строки, и `overflow:hidden` их обрезал.

## 28.4. Чему это учит (правило)

> Внутри `root` (он всегда ровно высоты виджета + `overflow:hidden`) ни один
> ребёнок не имеет права ставить CSS-пол (min-height/max-height-оценку),
> не помещающуюся в бюджет: дефицит не уходит в скролл, а перекрывается
> следующим сиблингом. Пол — только в `computeLayoutSize`, а панели — сжимаемые.

Строка `hintRow` с фиксированной высотой — часть того же правила: она не может
вырасти при появлении кнопок (v1.20 уже обжигался на этом с подсказкой).

# 29. Одна нода вместо двух: три режима + обложка из прогона (v1.24, 2026-09-18)

## 29.1. Задача

Раньше для работы нужны были ДВЕ ноды: «выдача» перед CLIP (текст в поток) и
«сейвер» после VAE Decode (получает картинку проводом и сохраняет запись с
обложкой). Причина — **кольцо в графе**:

```text
[Library] ──prompt_out──▶ CLIP ──▶ KSampler ──▶ VAE Decode ──image──▶ [Library]
     ▲                                                                     │
     └─────────────── цикл, ComfyUI валидирует граф как DAG ◀─────────────┘
```

Хочется: одна нода и переключатель — сохранять или выдавать.

## 29.2. Что снимает кольцо

Картинка нужна была только как обложка. Провод — не единственный способ её
передать: ComfyUI сам рассылает клиенту список созданных файлов в событии
`executed` (`apiSchema.ts`: `{node, display_node, prompt_id, output}`, где
`output.images = [{filename, subfolder, type}]`, есть также `video/audio/text`).

Поэтому обложка теперь **подтягивается после прогона** (deferred preview):

1. `execute()` сохраняет запись и кладёт в `ui` поле `saved_id` (список: id
   новой записи или существующей, которой не хватает обложки).
2. JS слушает `executed`: от своей ноды — запоминает `prompt_id → saved_id`
   (`st.pendingPreview`), от любого другого узла — первую картинку этого прогона.
3. На `execution_success` — `st.apiPost("/prompt_library/attach_preview",
   {id, filename, subfolder, type})` (упавший/прерванный прогон — ожидание снимается,
   запросов нет).
4. Сервер берёт файл из output/temp (`folder_paths.get_directory_by_type`),
   декодирует (`_load_image_file`) и пишет обложку тем же `_save_thumbnail`
   (512px PNG + встроенный workflow в записи), затем рассылает refresh.

Ожидания чистятся по количеству (≤20), без таймеров. Слушатели снимаются в
`onRemoved` (как §26.8), иначе удалённые ноды продолжали бы дёргать сервер.

**Две ловушки (обе кусались на живой проверке):**

1. **id в `onNodeCreated` НЕ назначен.** Конструктор `LGraphNode` ставит
   `UNASSIGNED_NODE_ID = -1` (LiteGraphGlobal: `node.onNodeCreated?.()` вызывается
   в `createNode` ДО `graph.add`, где присваивается реальный id). Первая версия
   кэшировала `st.nodeId = this.id` → всегда `-1` → рукопожатие не сходилось и
   обложка не прикреплялась. Решение: `st.ownId()` читает `this.id` В МОМЕНТ
   события и отсекает `-1`.
2. **Нода внутри subgraph** приходит с префиксным id (`"5:12"`): сверяем и
   `display_node`, и последний сегмент id.

**Позиция в графе не важна.** Если нода стоит ПОСЛЕ узлов вывода (позиция старого
сейвера), её `saved_id` приходит позже картинок — поэтому первая картинка прогона
сразу кладётся в запас `st.runImages` (`prompt_id → файл`) и подхватывается в
момент прихода `saved_id`. Чистится на `execution_success`/`execution_error`.

**Диагностика на живой (F12, без домыслов):** не найден `saved_id` / в прогоне нет картинок /
сервер отверг файл — в консоль идёт `[PromptLibrary] cover: …` или
`attach_preview failed: <status>`.

## 29.3. Режимы (одна нода)

| Режим | Выход `prompt_out` | Что с базой |
|---|---|---|
| `📥 Запись` | пусто | сохраняет входящий `source` |
| `📤 Выдача` | текст выбранной записи (иначе входящий) | ничего не сохраняет |
| `📤📥 Выдача + запись` | как в выдаче | выдаёт И сохраняет входящий |

`mode` — виджет-строка: старые значения остались валидными. С v1.25 `widgets_values`
= `[mode, selected, save_folder, pickup]` (старые массивы из 3 значений читаются:
`pickup` = `""`), см. §30.

**Совместимость (авто-обход).** До v1.24 «Запись» была сквозной: ноду ставили в
разрыв перед CLIP и архивировали каждый прогон. Поэтому если у `prompt_out` уже
есть провод (проверяем сериализованный граф в `extra_pnginfo` — `_output_linked`),
«Запись» продолжает пропускать текст сквозь и возвращает `mode_notice` — JS
показывает подсказку в нижней строке. Отключить провод — выход станет пустым.

## 29.4. Ограничения и что осталось

- Превью не появится, если прогон не создал ни картинок, ни видео, или если
  запись сохранялась без генерации — тогда ручное `📷 Прикрепить превью` (с v1.26
  и видео: кадр снимает браузер) или IMAGE-провод (остался как опция — он нужен,
  когда картинка не из этого прогона).
- Видео-прогон обложку ДАЁТ: первый кадр снимает PyAV (§31). До v1.26 файл
  попадал в `_load_image_file`, PIL его не открывал — обложка молча не появлялась.
- IMAGE-провод и выход вместе по-прежнему дают кольцо — `checkCycle` подсвечивает
  ноду и тостит, `ensureIssueSafe` предлагает отключить провод при переходе в
  выдающий режим.
- Берётся ПЕРВАЯ картинка прогона (батч/несколько узлов вывода — все равно первая).
- Вторая нода (Saver) больше не нужна, но старые графы с ней работают как есть.

# 30. Подхват финального текста из другого узла (v1.25, 2026-09-18)

## 30.1. Симптом и настоящая причина

Живой граф пользователя: нода в режиме `📤 Выдача` отдаёт выбранную карточку в
LLM-цепочку (`PreviewAny → Promt в LLM → Text String (User Prompt) → MASTER STYLE →
Переключатель → Итоговый Prompt`), а финальный текст надо было положить обратно
на вход той же ноды, чтобы он сохранился. ComfyUI отвечает:

> Обнаружены ошибки — Недопустимый рабочий процесс: в рабочем процессе обнаружено
> циклическое соединение узлов

и перечисляет узлы ровно этой цепочки. **Это не баг ноды**: ComfyUI исполняет
только ацикличный граф, а одна нода не может быть одновременно началом и концом
одной цепочки. У IMAGE-провода (§29) была та же природа — именно поэтому раньше
требовались две ноды.

## 30.2. Решение: отложенный подхват (deferred pickup)

1. **Настройка.** `pickup` — скрытый виджет (id узла-источника, `STRING`),
   видимый контрол — DOM-строка `pickupRow` «📎 Текст в базу:» (первая в `root`).
   Список собирается из живого графа: узлы верхнего уровня со `STRING`-выходом или
   строковым виджетом (`text`/`value`/`string`/`prompt`); своя нода, другие
   `PromptLibrary` и mute-узлы не предлагаются.
2. **execute() при включённом подхвате НЕ сохраняет входящий текст** (иначе на каждый
   Queue плодилась бы запись из провода, которого для этого случая и не подключают)
   и возвращает `mode_notice` — «входящий текст не сохраняется, запись берётся из
   узла №N после прогона» (ничего не происходит молча).
   Вместо сохранения — `_pickup_stash()`: снапшот воркфлоу и папка под токеном
   (`_PICKUP`, лимит 20, без таймеров — чистим по количеству), токен уходит в
   `ui.pickup` + `ui.pickup_node`.
3. **JS.** В `executed` ЛЮБОГО узла запоминается `output.text`,
   если он есть (`st.runTexts`; ключ — и полный id, и последний сегмент: нода
   внутри subgraph приходит как `"5:12"`). От своей ноды — `st.pendingPickup`
   (`prompt_id → {token, node, text}`). На `execution_success` (только успех):
   текст = текст прогона → фолбэк на виджет живого графа
   (`st.pickupText`) → `POST /prompt_library/save_pickup {token, text}` →
   обложка этого прогона через тот же `/attach_preview` (§29).
4. **Роут `/prompt_library/save_pickup`.** Токен одноразовый (`_PICKUP.pop`):
   неизвестный/повторный → 400; пустой текст → `skipped: "empty"` (не ошибка);
   дубль по тексту → `duplicate: true`. Запись создаётся с тем же воркфлоу-снапшотом,
   что и автосейв (карточка самодостаточна, §24).

**Почему не проводом:** граф должен остаться DAG, а финальный текст уже есть в
событиях прогона — `PromptKeeper` возвращает `{"ui": {"text": [text]}}`, то есть
любой OUTPUT-узел со строкой виден клиенту в `executed`.

## 30.3. Почему дубль не тостит

Подхват срабатывает на КАЖДЫЙ Queue. Если тост «дубликат не сохранён» показывать и
здесь, повторная генерация того же промпта поднимала бы попап каждый раз — поэтому
для подхвата дубль пишется в нижнюю строку ноды (`hintSticky`) и в F12
(`pickup: дубликат…`), без попапа. Тост оставлен только там, где запись ожидалась
явно (ручная кнопка, автосейв из `execute()`).

## 30.4. Ограничения (сознательные)

- В селекторе — только узлы ВЕРХНЕГО уровня графа (вложенные в subgraph не
  перечисляются; их id вида `"5:12"` всё равно матчатся по последнему сегменту).
- Если узел-источник не исполнился (кэш) и его виджет пуст — сохранять нечего
  (F12: `pickup: узел #N не отдал текст — запись не создана`).
- Если кэширована сама нода (`executed` не приходит) — подхвата нет (повторный
  идентичный прогон не создаёт второй записи, что и нужно).
- Mute-узлы не предлагаются (mute не исполняется); обложку даёт и видео-прогон — первый кадр (v1.26, §31).
- Список узлов пересобирается при создании ноды, после загрузки воркфлоу
  (`onConfigure`) и перед открытием селектора — без наблюдателей и таймеров.

## 30.5. Диагностика (F12, без догалок)

`pickup saved: <id> (узел #N)` · `pickup: дубликат, запись не создана` ·
`pickup: узел #N не отдал текст — запись не создана` ·
`save_pickup failed: <status> {…}` · `pickup: узел не найден в графе: <id>`.

## 30.6. Правило

Обратную петлю в графе не замыкать проводом: значение, которое появляется ТОЛЬКО
в момент прогона, забирается из его событий (`executed.ui.*`) и отправляется на
сервер вместе с токеном. Всё, что нужно позже (воркфлоу, папка), живёт в токене,
а не в URL и не в памяти клиента.

# 31. Медиа-обложка: видео из прогона, ручное видео и замена превью (v1.26, 2026-09-19)

## 31.1. Три жалобы и один корень

1. «Не сохраняет видео превью» — прогон с видео-выходом оставался без обложки.
2. «Нет возможности добавить превью из видео для ручного промпта» — `📷 Прикрепить
   превью` принимал только `image/*`.
3. «Нельзя заменить превью у существующей записи» — обложка ставилась один раз
   (без `force` второй раз не перетиралась, а клиента для этого не было).

**Корень первой:** файл прогон отдаёт нормально — ядро кладёт видео в то же
`images` (`PreviewVideo.as_dict()` → `{"images": [...], "animated": (True,)}`), а
сторонние ноды (VHS и подобные) — в `video`/`gifs`. Падало на сервере:
`_load_image_file` — это PIL, а PIL медиаконтейнер не открывает. Ошибка уходила
в `400 media read failed`, нода писала `attach_preview failed` в F12 — снаружи
выглядело как «видео не сохраняется».

## 31.2. Что сделано

- **Первый кадр видео (Python).** `_load_media_frame()`: сначала `_load_image_file`
  (PIL), при ошибке — `_load_video_frame()` через **PyAV** (`av.open` +
  `decode(video=0)`, лениво: нужен только кадр [0]). PyAV — штатная зависимость
  ComfyUI (её же использует `SaveVideo`/`VideoInput`), новых пакетов нет.
- **Тип обложки.** `_is_video_file()` по расширению (`mp4/webm/mkv/mov/m4v/avi/
  wmv/mpg/mpeg/flv`); анимированные GIF/WEBP остаются картинками — PIL берёт
  первый кадр сам. `media` теперь описывает ТЕКУЩУЮ обложку и обновляется с ней.
- **Файл прогона: все пулы.** JS берёт первый файл из `output.images` →
  `output.video` → `output.gifs` (раньше читался только `images`).
- **Кадр из браузера (preview_data).** `/attach_preview` принимает либо ссылку на
  файл прогона, либо PNG-dataURL кадра от браузера. Так приходит видео с диска
  пользователя (сервер такого файла не видит): `st.readPreviewFile()` рисует первый
  кадр через `<video>`+canvas, без библиотек. Картинка идёт тем же путём, что и
  раньше (canvas-даунскейл 512px).
- **Замена обложки.** В панели книги — кнопка `🖼/🎬 Заменить превью`: она
  **скрыта в режиме просмотра** и появляется только после ✏️ Редактировать (рядом
  с 💾) — случайно нажать её при рассматривании записи нельзя, и она ведёт себя как
  действие изменения, а не просмотра. Файл с диска → `preview_data` + `media` +
  `force: true`. Локальная метка `st.previewStamp` добавляет `&r=` к URL превью —
  без неё браузер показал бы старую картинку из кэша (`t=created_at` не менялся).
- **Подтверждение перед перезаписью.** Обложка хранится ОДНИМ файлом
  `previews/{id}.png`, поэтому замена стирает прежний кадр безвозвратно. Перед
  POST — диалог (`app.extensionManager.dialog.confirm`, фолбэк `confirm()`), в
  котором названо имя записи и что именно будет записано; отказ — обложка не
  трогается, подпись кнопки возвращается к текущему типу (как у удаления записи,
  которое тоже идёт через `confirm`).
- **Режим редактирования не сбрасывается.** После замены обновляются только
  формуляр, подпись кнопки и карточка списка: поля `название/категория/текст`
  остаются редактируемыми, несохранённый текст не теряется (`st.fillMeta`).
- **✖ Отмена в панели книги.** В режиме правки рядом с 💾 есть ✖ — выход без
  сохранения: значения берутся из базы заново (`st.fillDetail`, одна точка правды,
  а не второй ручной сброс полей). Диалог спрашивают только когда правки реально
  есть («зашёл и передумал» — тихий возврат); отказ в диалоге оставляет пользователя
  в режиме правки с введённым текстом. Это закрывает ту же дыру, что и гейт у
  замены обложки: «случайно тронул запись» не должно ничего терять.
- **Ручной промпт** принимает и видео: `accept="image/*,video/*"`, миниатюра
  выбранного файла (`<img>` для картинки, `<video>` для видео), `/add` пишет `media`
  вместе с превью (по метке работают 🎬/📷-бейдж и фильтр «Тип»).

## 31.3. Совместимость и границы

- Старые записи без `media` читаются как раньше (`null`). Ручное фото раньше
  сохранялось без метки — теперь метка ставится, и такая запись видна в фильтре
  «📷 Фото» (осознанное изменение).
- `attach_preview` без `force` по-прежнему не перетирает готовую обложку — в том
  числе когда пришёл `preview_data`.
- Ручная замена у удалённой записи отдаёт `404`; авто-подхват — по-прежнему
  `no_entry` (там это норма: запись могли удалить между Queue и концом прогона).
- Прежняя обложка НЕ архивируется: файл перезаписывается на месте, восстановить
  его нельзя. Поэтому и режим правки, и подтверждение — не косметика, а условие
  того, что запись меняется осознанно.
- Видео декодируется ПЕРВЫМ кадром (как и кадр из провода, §5); выбор кадра
  (середина, обложка из файла) не делаем.
- Браузер не смог прочитать файл (экзотический кодек) — обложки нет, но молчания
  тоже: стойкая подсказка + F12, текст записи сохраняется.
- Файлы больше 8 МБ в `preview_data` не принимаются (тот же лимит, что у ручного
  превью): кадр — PNG 512px, он в лимит укладывается с запасом.

## 31.4. Диагностика (F12)

`media read failed: <причина>` (файл прогона не декодировался) ·
`video frame: PyAV недоступен` / `video frame failed: <причина>` ·
`replace preview failed: <status>` · `preview: не удалось прочитать файл <имя>` ·
`preview_data rejected` (кадр не распознан как картинка).

## 31.5. Проверено без ComfyUI

Синтетический mp4 (PyAV, 3 кадра) → `_load_video_frame` = (48,64,3) uint8 →
`_save_thumbnail` = `previews/*.png`. Тесты: 19 проверок Python (снифф расширений,
видео через PyAV, подсказка `media` важнее расширения, `preview_data`, `force`,
`404` на удалённой записи, воркфлоу в новом превью, `media` из `/add`) и 4 фазы
смоука (пулы `images`/`video`/`gifs`, кадр из файла, гейт замены обложки с подтверждением, отмена правок).
