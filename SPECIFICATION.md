# Техническое задание (ТЗ) — Prompt Library для ComfyUI

**Версия:** v1.10 (воркфлоу в карточке + lazy-превью — проверено живьём)
**Связь:** продолжение серии Prompt Keeper (v1.0 — «последний промпт», Library — «база промптов»)

## Модель «как в реальной библиотеке»

Запись = книга в категории. Каталожная карточка: **название** (title), **аннотация** (полный текст промпта),
**категория** (внутреннее поле folder, путь `Фото/Портреты`), **обложка** (превью), формуляр: создана / выдана (`created_at` / `last_used`),
★ «список чтения» (favorite). Поиск — по названию и тексту. Порядок категории: сначала новые / по названию А–Я /
сначала старые / недавно выданные. Вид — как в проводнике Windows: 🖼 Крупные (163px сетка, по умолчанию),
🎞 Средние (109px сетка), 📋 Список (82px строки); выбор запоминается в localStorage. Ничего не выдумываем —
типовые библиотечные практики.

---

# 1. Цель проекта

Разработать кастомную ноду для ComfyUI **Prompt Library** — библиотеку промптов с категориями, поиском и превью изображений, которая:

- автоматически сохраняет промпты и превью в процессе генерации (если опция включена);
- позволяет всегда вернуться к ранее созданным промптам;
- по необходимости выдаёт нужный промпт в рабочий процесс.

# 2. Зафиксированные решения (опрос 2026-09-13)

| Вопрос | Решение |
|--------|---------|
| Архитектура | **Одна универсальная нода** (и сохраняет, и выдаёт). Отдельные Saver/Browser не делаем |
| Категории | Эволюция: сначала **свободная строка + избранное**, затем (по решению пользователя) **дерево категорий**: категории/подкатегории `Фото/Портреты` с созданием/переименованием/удалением + **имена записей**. Слово «полки» из интерфейса убрано — везде «категории» |
| Превью | **Вход IMAGE проводом** от VAE Decode / SaveImage. Автоподхват последнего изображения без провода не делаем |
| Хранение | **Внешний JSON + папка превью**. Не внутри workflow/PNG (как Keeper), а общая база для всех воркфлоу |

# 3. Назначение и схема работы

Универсальная нода стоит в разрыве текстового потока и параллельно принимает изображение для превью:

```text
LLM / Keeper / ручной ввод
        │
        ▼ (STRING)
  prompt ───┐
            ▼
     Prompt Library ──► prompt_out (STRING) ──► CLIP Text Encode
            ▲
            │ (IMAGE, optional)
VAE Decode / SaveImage
```

Два режима в одном проходе `execute()`:
1. **📥 Запись** — входящий `prompt` идёт на выход как есть + сохраняется в базу (если это не дубликат).
2. **📤 Выдача** — в UI выбрана запись из библиотеки — на выход идёт текст выбранной записи, записи нет.

# 4. Хранение данных (внешнее)

## 4.1. Расположение

```text
ComfyUI/user/prompt_library/
├── library.json
└── previews/
    └── {id}.png (legacy: {id}.jpg без метаданных)
```

- `user/` переживает обновление ноды и ComfyUI — выбрано сознательно.
- Путь резолвится от рабочей копии ComfyUI в рантайме (через `folder_paths` / `__file__`-относительно, уточнить на реализации).
- Удаление ноды базу не трёт.

## 4.2. Схема записи

`library.json` — объект `{"entries": [...], "folders": [...]}` (legacy: голый список — мигрирует автоматически).

```json
{
  "id": "a3f9c1e2",
  "title": "Дайвер в латунном шлеме",
  "prompt": "portrait, soft light...",
  "folder": "Фото/Портреты",
  "favorite": false,
  "created_at": "2026-09-13T12:00:00",
  "last_used": "2026-09-14T09:00:00",
  "preview": "previews/a3f9c1e2.png"
}
```

- Старые записи мигрируют: `category` → `folder`, `title` = первые 60 символов текста.
- Пустые категории хранятся в `folders` (иначе их было бы не показать в дереве).
- Удаление категории не теряет книги: записи переезжают в корень. Переименование двигает подкатегории и записи (префикс).

- `id` — 10 hex от MD5(`dedup_hash + timestamp`).
- Дедупликация: хеш MD5(`prompt + \n + folder`) уже есть в базе → не сохраняем повторно (возвращаем существующий id).
- `title` — имя книги; авто: первая строка текста до 60 символов; правится в панели книги.
- Лимит: 500 последних записей, новые вставляются в начало.
- Превью: PNG-тамбнейл, длинная сторона 512px (с запасом под крупный показ; в карточках даунскейлит браузер), ресемплинг LANCZOS, со встроенным чанком `workflow` (PngInfo — как у SaveImage; compact-JSON). Если вход `image` не подключён или пуст — запись без превью (`preview: null`). Старые JPG остаются как есть, при backfill'е workflow one-time апгрейдятся в PNG (§24.3).
- `category` оставлен дублем `folder` в записи — legacy-совместимость.

# 5. Входы

| Имя | Тип | Обяз. | Описание |
|-----|-----|-------|----------|
| `source` | `*` (ANY) | optional | Подписанный вход «Промт (вход)» — провод от LLM / Keeper / др. нод |
| `image` | IMAGE | optional | Провод для превью. Не создаёт виджета, только коннектор |
| `save_folder` | STRING (скрытый виджет, схлопнут) | required | Выбор дерева как есть: `""` = «Всё», `__fav`/`__root` = служебные ветки, иначе путь папки (пишет JS при каждом клике; персистится через `extra_pnginfo`; `onConfigure` восстанавливает). Python режет `__*` в корень — записи в служебные имена не сохраняются (§23.4) |
| `mode` | COMBO `📥 Запись` / `📤 Выдача` | required | Запись = сквозной выход + автосейв; Выдача = выход текстом выбранной книги |
| `selected` | STRING (hidden-виджет) | hidden/display | id выбранной записи. Пишется из JS, персистится через `extra_pnginfo` |
| `extra_pnginfo` | EXTRA_PNGINFO | hidden | Для патча workflow (как в Keeper) |
| `unique_id` | UNIQUE_ID | hidden | Для патча workflow (как в Keeper) |

**Ввод промпта:** в виджет `prompt` удалён. Ручной ввод через DOM-кнопку `➕ Добавить промпт` → textarea + `💾 Сохранить промпт` (POST `/prompt_library/add`). Вход `source` — провод от LLM / Keeper.

Нативную кнопку не используем: связка «DOM-окно + нативная кнопка» даёт щель при ресайзе (апстрим issue #7942).

# 6. Выходы

| Имя | Тип | Описание |
|-----|-----|----------|
| `prompt_out` | STRING | Итоговый текст: входящий (сквозной) или текст выбранной записи (режим `📤 Выдача`) |

Изменение текста на выходе запрещено (кроме выбора источника) — прозрачная нода, как Keeper. Второй выход `count` не делаем — счётчик виден в hint (`Записей в категории: N`).

# 7. Логика `execute()` (Python, `prompt_library_node.py`)

```
1. incoming = str(source), если `source` подключён; display = incoming
   issue = (mode == "📤 Выдача"); out_text = incoming; dirty = False
   если issue и selected-id найден:
       out_text = запись.prompt; запись.last_used = now; dirty = True
2. fld = norm(save_folder || kwargs.folder || kwargs.category) — legacy-Фолбэк для старых workflow
   если НЕ issue и incoming непустой и hash(incoming, fld) нет в базе:
       insert {id, hash, title=auto, prompt=incoming, folder=fld, favorite=False,
               created_at=now, last_used=None, preview=thumbnail(image) или null}
       entries = entries[:500]; добавить fld + родителей в folders; dirty = True
   если dirty: write library.json (атомарно: tmp + rename)
3. если extra_pnginfo + unique_id:
       патч workflow.nodes[id].widgets_values = [display, mode, selected, save_folder]
4. return {"ui": {"entries": до 200 × (id, title, head≤120, folder, favorite, created_at, last_used, has_preview),
                  "folders": [...], "selected": sel, "text": [display]},
           "result": (out_text,)}
```

Требования:
- `OUTPUT_NODE = True` (нужно для `{"ui": ...}` → `onExecuted` и для `extra_pnginfo`-патча).
- `FUNCTION = "execute"`, `CATEGORY = "My_custom_nodes/Prompts"`.
- `RETURN_TYPES = ("STRING",)`, `RETURN_NAMES = ("prompt_out",)`.
- Перезапись JSON целиком под каждый сейв допустима (база маленькая).
- Пустой `folder` = корень (`""`), без `"Без категории"`.
- `**kwargs["category"]` — совместимость со старыми workflow (виджет раньше назывался `category`).

Endpoints (`server.PromptServer`): GET `list` (`{entries` без `workflow`, но с
`has_workflow`, `folders}`) / `entry?id` (полная запись, включая `workflow`) /
`preview?id` (файл из записи, guard `previews/` + jpg|png, legacy-фолбэк);
POST `add` (ручное сохранение с кнопки, без workflow) / `favorite` / `update`
(title+prompt+folder, пересчёт hash) / `delete` (+ файл превью из записи) /
`folder_create` / `folder_rename` (движет префикс) / `folder_delete`
(записи переезжают в корень, не теряются).

# 8. JS-интерфейс (`web/js/prompt_library.js`)

Обычными виджетами не обойтись — нужен **DOM-виджет** внутри ноды (скил `comfyui-js-extension`).

## 8.1. Компоновка (сверху вниз)

Нативные виджеты ComfyUI (сверху вниз): `mode` (📥 Запись / 📤 Выдача), скрытые `selected` + `save_folder`. Нет виджета `prompt` — ручной ввод через DOM-кнопку. Кнопка и автосейв пишут в открытую в дереве категорию (корень — если «Всё»).

DOM-библиотека (`addDOMWidget`, сериализация выключена):
- **Тогл ручного ввода**: `➕ Добавить промпт` → показывает/скрывает textarea (4 строки) + `💾 Сохранить промпт` (POST `/prompt_library/add`). При переключении вызывает `syncNodeSize()` для подстройки высоты
- тулбар: вид (🖼 Крупные / 🎞 Средние / 📋 Список) → порядок категории (новые / А–Я / старые / недавно выданные) → поиск (название + текст, клиентский);
- ряд: слева список книг (`list`, `flex:1`) | справа дерево категорий (`treeBox`, `width:34%`):
  - `list` = flex column: `listHead`(22px, пустой спейсер) + `listContent`(480px, скролл, карточки)
  - `treeBox` = flex column: `treeHead`(22px, "Категории" + "+ Категория") + `tree`(480px, скролл)
  - Оба контейнера начинаются и заканчиваются на одном уровне (одинаковая структура)
  - `list` растягивается при ресайзе ноды (`flex:1`), `treeBox` — фиксированная доля (`34%`)
  - Категории: 📚 Всё, ★ Избранное, 📥 Без категории + вложенные 📁 с отступом; ✏️ переименовать, 🗑 удалить с переездом книг в корень; `+ Категория` создаёт категорию, в текущей — подкатегорию);
- drag & drop (нативный HTML5, без библиотек): книга тащится на строку категории / на фон списка открытой категории (переезд через POST `update`); категория тащится в другую категорию или на 📚 Всё/📥 Без категории (переезд в корень через POST `folder_rename`); дроп на себя/внутрь себя и на текущее место — игнор; дроп-зона подсвечивается пунктиром;
- карточка: обложка, название жирным, начало текста (в списке), категория · даты, ★/🗑;
- панель книги: название, категория, полный текст, формуляр (`№ id · создана · выдана`), 📋 Копировать (clipboard + fallback), ✏️/💾 редактирование (POST `update`).

## 8.2. Хуки LiteGraph

- `onNodeCreated` — DOM-виджет (с `computeSize` с фиксированными константами), схлопывание технических `selected`/`save_folder`, первичная загрузка через `reload()` (GET `list`).
- `onExecuted(message)` — пришедшие `entries` → полный `reload()`; `selected` → виджет. **Не пишет** в виджет `prompt` (его больше нет).
- `onConfigure(info)` — синхронный restore папки из данных воркфлоу
  (`info.widgets_values_named.save_folder`, фолбэк — `info.widgets_values[2]`
  по порядку INPUT_TYPES) + одноразовый reconcile после `reload()` (виджет
  побеждает, иначе sync-значение, мусор → корень). Ноль таймеров (§23).
- `onConnectionsChange` — только сторож цикла.
- Поиск/фильтр/сортировка — чистый JS по `entries`.
- Клик по карточке → `selected = id` + панель книги (GET `entry` с кэшем). Режим **не** переключается автоматически.
- Защита от кольца (JS, без участия Python — цикл виден только по проводам): переход в Выдачу при подключённом `image` показывает confirm «отключить IMAGE-провод?»; при отмене `mode` возвращается на «📥 Запись» (`ensureIssueSafe()` возвращает bool). Сторож `checkCycle` (`onConnectionsChange`/`onConfigure`/`onNodeCreated`) красит ноду в красный + toast, если `image` подключён И выход куда-то ведёт; снимается сам при исправлении. Переключение папки сбрасывает `detailId`, `selWidget.value` и скрывает detail-панель.
- Автосокеты (фронтенд 1.52 даёт сокет каждому виджету, `getWidgetConfig`, тип `*` — проверено в установленном бандле): у `selected`/`save_folder` автосокеты удаляются (`dropAutoSockets` через `removeInput`, только неподключённые). Остаются ровно два подписанных входа: `source`, `image`. Подключённые не трогаем.
- ★/🗑 записи и ✏️/🗑 папок — прямые POST на endpoints + `reload()`; удаления через `confirm()`.

## 8.3. Стиль

Тёмная тема под ComfyUI. Дерево и список со своим скроллом (max-height ~300–336px). Превью отдаёт endpoint `GET /prompt_library/preview?id=` напрямую файлом (без чтения базы: `png → jpg`; `Last-Modified` → дешёвые 304). В JS стабильный `t=created_at` (не `Date.now()` — иначе перезакачка всех превью при каждом рендере) + `loading="lazy"`.

# 9. Поиск, категории, порядок (правила)

- Поиск — по подстроке в названии + тексте + категории, case-insensitive, клиентский.
- Категория — путь через `/` (`Фото/Портреты`); нормализация режет пробелы и пустые сегменты; пусто = корень.
- Родительские категории дерева выводятся автоматически из путей записей.
- Избранное — boolean-флаг, ★-тоггл, фильтр `★ Избранное`.
- Порядок категории: сначала новые (default) / по названию А–Я (`localeCompare ru`) / сначала старые / недавно выданные (`last_used`).
- Переименование категории двигает префикс у подкатегорий и записей; удаление категории переносит её книги в корень.

# 10. Персистентность (наследие Keeper, скил `comfyui-png-persistence`)

Проблема Keeper сохраняется: workflow JSON захватывается до выполнения → виджеты пусты в PNG.

- Решение то же: патч `extra_pnginfo['workflow'].nodes[unique_id].widgets_values` на стороне Python.
- Персистим: `[mode, selected, save_folder]` (порядок = порядок INPUT_TYPES).
- Сама база (`library.json`) в PNG не дублируется — только выбор и настройки.
- Билингва виджетов — через `locales/{lang}/nodeDefs.json` (скилы `comfyui-localization`, `comfyui-bilingual-node`), паттерн — из Keeper.

# 12. Ограничения (не делаем)

- Автоподхват последнего изображения без провода.
- Экспорт/импорт базы (TXT/JSON), облачная синхронизация.
- Пагинация/виртуализация больше 500 записей (только первые 200 в UI-пакет + поиск).
- Множественный выбор / пакетная выдача.
- Теги отдельно от папок (пока хватает полок + избранного).
- Endpoint-авторизация / многопользовательность — локальный ComfyUI, один пользователь.

# 18. Sizing DOM-виджета: анализ и решения (2026-09-15)

## 18.1. Три найденные проблемы и их корни

### Проблема 1: Бесконечное вытягивание вниз
**Симптом:** нода растёт без остановки при создании/загрузке.
**Корень:** `computeSize` использовал `root.scrollHeight` — полную высоту DOM-дерева.
У `list` и `tree` стоит `overflow:auto` (визуально 480px), но `scrollHeight`
считает **все** строки: 100 карточек × 200px = 20,000px → нода растягивается.
**Решение:** `computeSize` возвращает фиксированные константы из стейта виджета.

### Проблема 2: Нода «пляшет» при зуме
**Симптом:** при изменении масштаба канваса нода прыгает вверх-вниз.
**Корень:** `computeSize` делил высоту на `plScale()` (зум канваса). При зуме 0.5×
фронтенд получал высоту ×2 → растягивал ноду → `computeSize` вызывался снова →
обратная связь. Дополнительно: `offsetHeight` нестабилен во время layout-пересчётов.
**Решение:** убрано деление на `plScale()`, убран `offsetHeight` — фиксированные константы.

### Проблема 3: Пустое пространство снизу
**Симптом:** после удаления `computeSize` фронтенд даёт DOM-виджету дефолтную
высоту (~420px), которая не совпадает с реальным контентом.
**Корень:** фронтенд 1.52 не может точно вычислить высоту кастомного DOM без подсказки.
**Решение:** `computeSize` с фиксированными константами, вычисленными из реального контента.

## 18.2. Почему другие подходы не работали

| Подход | Почему не работает |
|--------|-------------------|
| `root.scrollHeight` | Считает скрытый контент `overflow:auto` → бесконечный рост |
| `offsetHeight` элементов | Нестабилен при layout-пересчётах (zoom, resize) → обратная связь |
| Деление на `plScale()` | При зуме фронтенд получает разную высоту → «танцы» |
| `fitNode` + `Math.max` | Нода может только расти,never сжиматься → застряет на максимуме |
| CSS-инъекции / таймеры / наблюдатели | Колхоз, ломается при обновлениях фронтенда |
| Override `this.computeSize` на ноде | Фронтенд использует для определения размера ноды → mismatch |

## 18.3. Текущее решение: фиксированные константы + detail max-height

```js
const DETAIL_H = 280; // detail-панель: title + folder + textarea(10rows) + meta + buttons
const BASE_H = 596;   // toolbar(30) + main(486) + hint(20) + gaps(30) + input area (~30)
const INPUT_H = 130;  // toggle input area (textarea 4 rows + save button)

browserWidget.computeSize = (w) => {
    const showDetail = detail && detail.style.display !== "none";
    const showInput = inputVisible;
    return [w || this.size[0], BASE_H + (showDetail ? DETAIL_H : 0) + (showInput ? INPUT_H : 0)];
};
```

**Почему это работает:**
- Константы вычислены один раз из реального контента (см. раздел 18.4)
- `computeSize` детерминирован: одинаковый вход → одинаковый выход
- Нет обратной связи с DOM (ни `offsetHeight`, ни `scrollHeight`)
- Нет зависимости от зума (`plScale` удалён)
- Фронтенд доверяет результату и не пересчитывает

## 18.4. Вычисление констант

Контент `root` (flex column, gap:6px):

| Элемент | Высота | Как вычислено |
|---------|--------|---------------|
| `inputToggle` | 30px | padding:4px × 2 + font:12px + border:1px × 2 ≈ 30px |
| `toolbar` | 30px | padding:4px × 2 + font:12px + border:1px × 2 ≈ 30px |
| `main` | 486px | list(480px) + gap(6px); tree(480px) в treeBox |
| `detail` | 280px | title(28) + folder(28) + textarea(170) + meta(14) + buttons(28) + gaps |
| `hint` | 20px | font:11px + line-height ≈ 20px |
| gaps (5 шт) | 30px | 5 × 6px = 30px |

**BASE_H** = 30 + 30 + 486 + 20 + 30 = **596px** (без detail и input area)
**С detail** = 596 + 280 = **876px**
**С input area** = 596 + 130 = **726px**
**С detail + input area** = 596 + 280 + 130 = **1006px**

## 18.6. Паттерн для других DOM-виджетов ComfyUI

При создании DOM-виджета с `addDOMWidget`:

1. **Определи фиксированные высоты** каждого видимого элемента (padding + font + border)
2. **Запиши константы** в `computeSize` — без `offsetHeight`, `scrollHeight`, `plScale`
3. **Не используй** `fitNode`, таймеры, наблюдатели, CSS-инъекции для sizing
4. **Вызывай `setSize`** только при изменении visible состояния (показ/скрытие панелей)
5. **Не дели на `plScale()`** — canvas-трансформация применяется фронтендом к container div
6. **Не перезаписывай `this.computeSize` на ноде** — ломает border/resize (проверено)

Если контент динамический (список растёт) — используй `overflow:auto` с фиксированной
высотой на контейнере, `computeSize` считай по контейнеру, а не по содержимому.

При пустом main он всё ещё занимает место → sidebar не «улетает».

**Textarea в detail:** `resize:none; rows=10; overflow-y:auto`. Уголок ресайза — нет.
Ограничение высоты через `max-height` на родителе (detail), а не на textarea.

# 19. Аудит ошибок (deep audit, 2026-09-15)

## 19.1. Python: isinstance(source, str) — защита от IMAGE-тензора

**Проблема:** `source` объявлен как `("*", {})` — ANY-тип. Если подключить IMAGE
(тензор), `str(source)` вернёт `"<torch.Tensor object at 0x...>"` → мусор в промпте.

**Решение:**
```python
if source is not None and isinstance(source, str):
    incoming = source.strip()
else:
    incoming = ""
```

## 19.2. Python: дедупликация через _add_entry вместо ручного кода

**Проблема:** `execute()` содержал копию логики `_add_entry()` (dedup + insert),
дублируя код. Пропущен параметр `title`.

**Решение:** `execute()` вызывает `_add_entry(entries, incoming, fld)` —
единая точка дедупликации и вставки.

## 19.3. Python: preview сохраняется ПОСЛЕ _add_entry

**Проблема:** `_save_thumbnail(image, entry_id)` требует `entry_id`, но `entry_id`
создаётся внутри `_add_entry()`. Нельзя вызвать `_save_thumbnail` до `_add_entry`.

**Решение:** сначала `_add_entry` возвращает `entry_id`, потом `_save_thumbnail`
сохраняет превью, потом patch обновляет поле `preview` в записи.

## 19.4. JS: sort comparator возвращает 0 при равенстве

**Проблема:** Компараторы `old`, `used`, `new` возвращали только `-1` или `1`,
никогда `0` при равных таймстемпах → недетерминированный порядок (мерцание списка).

**Решение:**
```js
ts(a.created_at) < ts(b.created_at) ? -1 : ts(a.created_at) > ts(b.created_at) ? 1 : 0
```

## 19.5. JS: console.log → console.debug

**Проблема:** Debug-лог `[PromptLibrary] build 20260915-audit` в production-коде
засорял консоль.

**Решение:** заменён на `console.debug`.

## 19.6. Оставлено без изменений (осознанно)

- **Race condition `_load_db()`** — нет file-locking, но `os.replace` атомарен.
  При параллельных HTTP-запросах возможна потеря данных. Приоритет: низкий
  (один пользователь, последовательные запросы).
- **`reload()` молча глотает ошибки** — по design: не спамить toast при старте.
- **Double render в `onConfigure`** — `reload()` + `.then()` вызывают render
  дважды, но это корректно (данные обновляются между вызовами).
- **`BASE_H=436`** — константа, пересчитывается при визуальных изменениях.
- **`_pl_list` без кэша** — полное чтение JSON при каждом запросе. Для <500
  записей приемлемо.

# 21. Эксперименты с flex stretch (2026-09-16) — НЕ УДАЛОСЬ

## 21.1. Цель

Сделать так, чтобы контент (list/tree) растягивался вместе с нодой при ресайзе
(как нормальное окно), а не был фиксированных 480px. Низ ноды должен
«примыкать» к контенту.

## 21.2. Попытки и результаты

| # | Попытка | Результат |
|---|---------|-----------|
| 1 | `flex:1` на list/tree вместо `height:480px` | **Feedback loop**: `computeSize` читает `scrollHeight` → DOM заполняет ноду → `scrollHeight` = высота ноды → бесконечный цикл. Нода растёт бесконечно |
| 2 | Offscreen measurement (cloneNode) | **Сломало всё**: clone с `flex:1` создавал бесконечную высоту |
| 3 | Убрал `computeSize` override | Нода失去了 фиксированный размер, content залипает |
| 4 | `resizable=true` + `onResize` clamps | Низ ноды не сжимается — `computeSize` возвращает min height, `onResize` не может уменьшить |
| 5 | Убрал `resizable=true` | `resizable=false` запрещает ресайс вообще — пользователь не может тянуть |
| 6 | Убрал `computeSize` override | Фронтенд даёт дефолтную высоту (~420px), не совпадающую с реальным контентом |

## 21.3. Корневая причина

`computeSize` — единственный способ фронтенду узнать высоту DOM-виджета.
Он читает `scrollHeight` (или должен возвращать фиксированную константу).
Если DOM заполняет ноду через `flex:1` → `scrollHeight` = высота ноды →
`computeSize` возвращает эту высоту → фронтенд устанавливает эту высоту → loop.

**Нельзя одновременно:**
- чтобы контент растягивался с нодой (flex:1)
- и чтобы `computeSize` возвращал детерминированную высоту

Это фундаментальное ограничение архитектуры DOM-виджетов ComfyUI.

## 21.4. Вывод (для будущих агентов)

**НЕ ПОВТОРЯТЬ:**
- `flex:1` на list/tree/content — создаёт feedback loop с `computeSize`
- Offscreen measurement с cloneNode — clone наследует `flex:1`, ломает всё
- Убирание `computeSize` — фронтенд даёт неправильную дефолтную высоту
- `resizable=true` + `onResize` — не может уменьшить ноду меньше `computeSize`
- Любые CSS-хаки для «прилипания» низа — всё создаёт обратную связь

**Единственное стабильное решение:** фиксированные константы в `computeSize`
(`BASE_H=596`, `DETAIL_H=280`, `INPUT_H=130`). Контент прокручивается
внутри фиксированных контейнеров. Нода не «прилипает» к контенту — это
компромисс, но стабильный.

## 21.5. Текущее состояние (архив: решено в §22)

- ~~Низ ноды не примыкает к контенту~~ — решено переходом на `computeLayoutSize`
  (§22): ограничение было у legacy `computeSize`, а не фундаментальным.
- Деталь истории неудачных попыток выше (§21.1–21.4) — не повторять подходы
  с чтением размеров DOM в sizing-методе.

# 22. Вертикальный stretch через computeLayoutSize (2026-09-17) — РЕШЕНО

## 22.1. Проблема

При растягивании ноды в сторону контент тянулся, при растягивании вниз —
нет: внутри оставалось пустое пространство, низ не примыкал к контенту.

## 22.2. Корень (найден в исходниках фронтенда, `settingStore-*.js`)

`_arrangeWidgets` имеет две ветки:

- виджет с legacy **`computeSize`** → `computedHeight = computeSize()[1] + 4`
  — **точная** высота, свободное место ноды ему не достаётся;
- виджет с **`computeLayoutSize`** → `{minHeight, maxHeight}` →
  `distributeSpace` отдаёт ему **всё свободное место** (лимит по умолчанию —
  бесконечность). Так работают штатные video/image-превью.

Наш `browserWidget` задавал legacy `computeSize` → 596/876px намертво.
Vue-обёртка `WidgetDOM` (`flex flex-col *:flex-1`) и так растягивает наш
`root` — растягивать было нечего, виджету всегда давали ровно 596.

## 22.3. Решение (не повтор §21)

- `browserWidget.computeSize` **убран**, вместо него
  `browserWidget.computeLayoutSize = () => ({minHeight, minWidth})`,
  где `minHeight = BASE_H + DETAIL_H + INPUT_H` по boolean-стейту
  (попутно починен пропуск `INPUT_H` в старом `computeSize`).
- CSS-цепочка: `root height:100%` → `main flex:1` →
  `listContent`/`tree`: `height:480px` → `flex:1 + min-height:480px`
  (floor = старый фикс. размер, вид без ресайза не меняется).
- Почему это не §21: `computeLayoutSize` читает только boolean-стейт
  (`display`-флаги), а не размеры DOM → детерминирован, feedback loop
  невозможен по построению.

## 22.4. Статус

Проверено живьём пользователем 2026-09-17: drag вниз тянет контент, пустоты
нет, зум без «плясок». Принято (canvas-режим).

## 22.6. Двухрежимный layout: Vue (Nodes 2.0) vs canvas (механика из исходников)

- Min width в Vue = `node.style.min-width` инлайн или 225 (`useNodeResize`);
  наш MIN_W через `setSize` туда не доходит → ставим напрямую на `[data-node-id]`
  (в канвасе элемента нет → no-op). Лечит вываливание контента вправо.
- Min height Vue меряет сам (`measureMinContentHeight`: обнуляет высоту, меряет
  контент) — низ примыкает руками: потянуть вниз до упора + сохранить workflow.
  Высокий размер при открытии = сохранённый (эпоха canvas-stretch), не баг.

Факт из исходников: Vue-обёртка `WidgetDOM` (`flex flex-col *:flex-1`) без
высоты — content-sized. Flex-цепочка (§22.3) там нечем ограничить: все карточки
наружу, скролла нет, нода растягивается и не сжимается.

Решение: `st.applyPaneLayout()` по флагу `Comfy.VueNodes.Enabled` (чтение по
документированному Settings API: `app.extensionManager.setting.get(id)`,
фолбэк — `app.ui.settings.getSettingValue`; подписка на `.change`): Vue —
фиксированные 480px у `tree`/`listContent` (скролл всегда, как v1.7), canvas —
flex stretch. NB: чтение через `app.ui.settings` напрямую НЕ работает
(молча false) — только через `extensionManager.setting`.
`computeLayoutSize`-минимум общий для обоих режимов. Переключение режима без
reload подхватывается подпиской + повторным вызовом в `onConfigure`.

## 22.7. Vue-режим: auto-fit через прокси размера (без борьбы с layout)

Исправление прошлой ошибки: `setSize` в Vue РАБОТАЕТ — `node.size` это Proxy,
запись коммитит в layout store (`resizeNode`, source=Canvas), а платформа не
перекоммичивает без изменений (`isSizeEqual`, сходимость встроена). Вывод
«setSize мёртв» был неверен: код hug ни разу не запустился (флаг `_vuePanes`
не присваивался), проверять было нечего. Дёргавшая проба (−120/+120) удалена.

Механика `st.autoFitHeight()` (только Vue; в канвасе stretch): панели
фиксированы → контент не зависит от размера → таргет стабилен. Chrome
калибруется минимумом, зум делится (`ds.scale`), пол из `st.minH()`, deadband
4px, антиспам при несдвинувшейся ноде и том же контенте. Вызывается на
дискретных сменах контента (конец `render()`, тоглы, `onResize` — в Vue он
редок, вреда нет). Таймеров, наблюдателей, скрапинга DOM нет. Смена коннектов
сбрасывает калибровку chrome.

## 22.8. Статус Vue-фита: НЕ работает живьём, изъян найден (2026-09-17)

Пользователь: после рестарта ComfyUI и замены ноды — абсолютно без изменений.
Круговое хождение признано, работа передана другой модели.

Честный разбор изъяна (мой): калибровка `chromeMin` самоблокируется на высокой
ноде. Первая же выборка: `chrome = nodeH − content` включает ВЕСЬ surplus
(нода 2000, контент 900 → chrome=1100) → `target = content + chrome = nodeH` →
deadband «сошлось» → больше никогда не двигается. Минимум, который может только
уменьшаться, никогда не уменьшится: чтобы узнать истинный chrome, нужен момент
примыкания, которого нет. Замкнутый круг.

Факты, установленные достоверно (не терять):
- `node.size` — Proxy, запись коммитит в layout store (`resizeNode`);
  `isSizeEqual` даёт сходимость; `measureMinContentHeight` меряет минимум по
  контенту; min-width = инлайн или 225 (`useNodeResize`).
- Детект Vue через `app.extensionManager.setting.get('Comfy.VueNodes.Enabled')`
  (напрямую `app.ui.settings` — молча false). Панели 480 + скролл в Vue работают.
- Правильное направление: chrome НЕ выводить из (высокая нода − контент);
  нужен независимый замер рамки (шапка ноды напрямую) или константа.
  Канвас-режим при этом не трогать (там stretch работает, проверено). Пол `_vueFloor` из замера оставлен как фолбэк
для минимумов.

# 23. Восстановление папки при открытии: гонка со store hydration (2026-09-17)

## 23.1. Факты (проверены, не гипотезы)

- **Save-сторона в порядке**: в workflow-файле `widgets_values_named.save_folder`
  корректен (проверено в `Krea2_MY2.json`: `"save_folder": "Fs/FAS"`), папка
  есть в `library.json`. Потеря на вкладках без рестарта — тот же load-путь.
- **Load-сторона**: одноразовый restore в `onConfigure` (даже через `rAF` + `fetch`)
  не срабатывал — в момент проверки `save_folder`-виджет ещё пуст.
- **Вывод**: новый фронтенд применяет `widgets_values` к виджетам **асинхронно**
  (widget store hydration) после создания ноды; синхронного уведомления об
  окончании на момент исследования не найдено.
- Режим при этом восстанавливался сам (фронтенд доприменяет позже), а кастомный
  JS-стейт (`selFolder`) — нет: наш restore уже отработал и пропустил.

## 23.2. Решение (без polling): sync-из-info + одноразовый reconcile

Исследование ядра (`LGraphNode.configure`): значения виджетов применяются
синхронно, затем вызывается `onConfigure(info)` — а `info` это сами данные
воркфлоу (`widgets_values` + `widgets_values_named`). Вывод: ждать hydration
виджетов не нужно вообще.

- **Sync-fase** в `onConfigure(info)`: `save_folder` из
  `info.widgets_values_named.save_folder`, фолбэк — `info.widgets_values[2]`
  (порядок INPUT_TYPES required `[mode, selected, save_folder]`, SPEC §10;
  совпадает и со старыми 4-элементными массивами). Сразу `st.selFolder = v` —
  первый рендер после fetch уже правильная папка, кадра «Всё» нет.
- **Reconcile-fase** (один `.then` после `reload()`, без таймеров): виджет
  (если гидрация донесла) побеждает, иначе держим sync-значение, мусор
  (папка удалена из базы) → `"__all"`. Клики всегда синхронизируют виджет
  и `selFolder`, поэтому сверка никогда не спорит с пользователем.
- Попутно: `syncSaveFolder` ищет виджет заново при каждом вызове
  (не кэширует ссылку); `browserWidget.serialize = false` выставлен
  **свойством** (`options.serialize` не пробрасывается — в файле был лишний
  4-й value `pl_browser:""`).
- Промежуточный retry (`st.restoreFolder`, 5×400мс) **удалён полностью**:
  в пути restore ноль `setTimeout`. Оставшиеся в файле `setTimeout` — только
  сбросы подписей кнопок (UX-фидбэк, к restore не относятся).

## 23.3. Критерий профессионального решения (выполнен)

Ни одного `setTimeout`-retry в пути restore; restore не зависит от таймингов
фронтенда (sync из данных воркфлоу); мигание сведено к задержке fetch записей
(неустранимый минимум — список нечем рисовать, пока нет данных).

## 23.4. Служебные ветки тоже персистятся (v1.9.1)

Баг: на «Избранном» (`__fav`) / «Без категории» (`__root`) выбор сбрасывался
на «Всё» — `syncSaveFolder` маппил любой `__*` в `""`, и восстановить было
не из чего (пробел с самого начала, не регрессия).

Решение: виджет несёт выбор как есть (`""` только для `__all`), reconcile
считает валидными `__all`/`__fav`/`__root` + папки из базы. `execute()` на
входе режет `str(folder).startswith("__")` в `""` — новые записи из этих
режимов сохраняются в корень, папка `__fav` в базе невозможна. Старые файлы
(там `""`) открываются как «Всё» — что не было сохранено, не восстановить.

Проверено живьём пользователем 2026-09-17: Избранное и Без категории держатся
при переключении вкладок; Queue из этих режимов пишет в корень. Принято.

# 24. Воркфлоу в карточке: drag на канвас открывает граф (v1.10, проверено живьём)

## 24.1. Замысел

ComfyUI сохраняет изображение вместе с воркфлоу и настройками — превью в Library
несёт то же самое: карточка = промпт + превью + воркфлоу, который её создал.
Потянул карточку на канвас (или «📥 Воркфлоу» в панели книги) — открылся граф,
как при дропе PNG с workflow. Искать файлы не нужно: тут и база промптов, и воркфлоу.

## 24.2. Два слоя (оба)

1. **Превью-файл самодостаточен**: PNG 512px с чанком `workflow` (PngInfo) —
   как у SaveImage. Drag из проводника открывает воркфлоу нативно, без нашего кода.
2. **Воркфлоу в записи** (`library.json`): для drag'а с карточки и кнопки —
   без файлового round-trip. В `/list` и UI-пакете вырезан (тяжёлый), отдаётся
   флаг `has_workflow`; полный — только в `/entry` по клику.

## 24.3. Захват (Python, `prompt_library_node.py`)

- `execute()`: `_snapshot_workflow(extra_pnginfo)` — deep-copy (json round-trip)
  + кап 2МБ от патологических графов. Снапшот — pre-patch (как было на Queue).
- Минификация (вариант 1+3): `separators=(",", ":")` в снапшоте и чанке —
  данные идентичны (round-trip проверен), экономия ~4% на большом реальном
  графе (352→339 КБ), на pretty-JSON до ~20%. Старые записи — как есть.
- Новая запись: workflow в запись + `_save_thumbnail(..., workflow)` →
  `previews/{id}.png` с чанком.
- Дедуп-хит без workflow: backfill + one-time апгрейд JPG→PNG с метаданными
  (`_upgrade_preview_to_png`; старые JPG без workflow остаются как есть —
  не из чего восстановить).
- Ручное сохранение (`/add`) — без workflow (`has_workflow=false`).

## 24.4. Открытие (JS, `prompt_library.js`)

- `app.loadGraphData(workflow)` — штатный API замены графа (проверен в
  `settingStore-*.js`), всегда через confirm (деструктивно).
- Drag: `dragstart` ставит `application/x-pl-entry` (+ `text/plain` для папок);
  capture-хуки `dragover`/`drop` на `app.canvas.canvas`, один раз
  (`window.__plCanvasDropHooked`); чужое не трогаем (проверка типа, иначе return;
  свой — `stopImmediatePropagation`, чтобы файловый хендлер не сработал).
- Кнопка «📥 Воркфлоу» в панели книги (видна при `full.workflow`);
  title-подсказки на карточках; без workflow — warn-toast с объяснением.
